# Celnet — State-of-the-Art Scan (through May 2026)

> **Status:** Analysis / decision doc. No code. Surveys the most recent (≤ May 2026)
> academic + industry advances applicable to Celnet, critiques each against our binding
> constraints — **correctness, the §1.2 latency/throughput budget, determinism, compliance,
> and OSS-only (CLAUDE.md rule 7)** — and gives a concrete **adopt / defer / reject** verdict
> with the crate + method to use.
>
> **How to read a verdict.** Every candidate is scored on five axes:
> 1. **Real improvement?** — measurably better than what `docs/ARCHITECTURE.md` /
>    `docs/ANALYTICS-SPEC.md` already specify, not just novel.
> 2. **OSS / free?** — permissive licence (MIT/Apache-2.0/BSD), no commercial/runtime-paid dep.
> 3. **Deterministic?** — bit-identical across OS/arch/rebuild (CLAUDE.md determinism rule).
> 4. **In latency budget?** — fits the relevant NFR tier (hot 2–25 µs, surface 150 µs,
>    exotic interactive 50 ms), or is explicitly off-hot-path.
> 5. **Compliant / auditable?** — reference-validatable against QuantLib/published prices,
>    explainable to a model-validation / FRTB-IPV function.
>
> A method that fails **correctness, determinism, or compliance is rejected for the pricing
> path regardless of speed** — a fast wrong or unauditable price is worthless
> (ARCHITECTURE §1.1.4). Hype is flagged explicitly.

## 1. FX-options analytics — smile / surface, LSV, exotics

### 1.1 Arbitrage-free surfaces

**Current baseline (ANALYTICS-SPEC §3):** VV (Castagna-Mercurio 2nd approx), SABR (Hagan
2002 + arb-free PDE SABR 2014), raw SVI per slice, **SSVI** (Gatheral-Jacquier 2014) as the
globally arb-free production surface, with butterfly/calendar/vertical gates.

#### (a) eSSVI — extended SSVI with maturity-dependent correlation — **ADOPT**
- **What:** eSSVI lets the SSVI correlation ρ become maturity-dependent, ρ(θ_t), and yields
  **explicit closed-form necessary-and-sufficient** conditions for no calendar-spread and no
  butterfly arbitrage across the *whole* surface. Recent work (Corbetta–Cohort–Laachir–Martini
  2022, "No-arbitrage global parametrization for the eSSVI surface", arXiv:2204.00312;
  Mingone "eSSVI surface calibration" arXiv:2304.02106, 2023; Hendriks–Martini robust
  slice-by-slice calibration arXiv:1804.04924) gives a **forward slice-by-slice** algorithm
  that anchors each slice through the data point nearest the forward and stays arb-free even
  under naïve parameter interpolation. Validated on FX (NIS/USD) end-of-day surfaces.
- **Real improvement?** Yes — standard SSVI's single constant ρ is too rigid for the FX skew
  term structure (RR sign/magnitude varies strongly by tenor). eSSVI is a strict superset and
  fits the broker 5-point (ATM/25d/10d RR-BF) term structure better while *preserving* the
  closed-form no-arb guarantee we rely on for Dupire stripping.
- **OSS/free?** Pure math; we implement it. No dependency.
- **Deterministic / latency / compliant?** Yes on all three — it's a small nonlinear LS
  calibration with analytic constraints, comfortably inside the 150 µs surface-rebuild budget
  for a single pair/all-tenors, and fully reference-validatable (re-price the input quotes).
- **Verdict:** **ADOPT** into `celnet-surface` as the production arb-free parametrization,
  with SSVI retained as the constrained special case (ρ constant). Keep VV as the fast
  indicative/extrapolation engine and SABR-PDE for deep wings. Cross-check eSSVI density ≥ 0
  on every rebuild (we already gate this).

#### (b) HyperIV — hypernetwork real-time IV smoothing (ICML 2025) — **DEFER (sandbox / advisory)**
- **What:** A hypernetwork emits the weights of a compact NN that produces a *complete*
  static-arbitrage-free surface from ~9 quotes in **~2 ms**, no per-surface calibration
  (Yang–Chen–Shu–Hospedales, ICML 2025; code `github.com/qmfin/hyperiv`, **MIT**, PyTorch/
  Python, requires training, no obvious shipped pretrained weights). Tested on **index**
  options.
- **Real improvement?** Partially. The "no calibration, 2 ms" framing under-sells what we
  have: our eSSVI/VV path is already inside 150 µs and is *exact* on the inputs. HyperIV's
  win is robustness/smoothness from sparse, noisy quotes and cross-asset generalization — not
  raw speed vs us.
- **OSS/free?** Code is MIT, but it's **Python/PyTorch** and ships as a *training recipe*,
  not a deterministic Rust analytic. Pulling a Torch runtime into the hot path is a non-starter.
- **Deterministic / compliant?** **No** — the surface is a function of trained float weights;
  reproducing it bit-identically across platforms/retrains is not guaranteed, and a model-
  validation function cannot read a "why" out of the hypernet. It would be an unauditable mark.
- **Verdict:** **DEFER.** Two narrow, *correctness-safe* uses if ever: (1) an **advisory**
  cross-check / outlier flag against the eSSVI mark (never the booked surface); (2) a
  **warm-start** that seeds eSSVI parameters, after which the deterministic calibrator owns
  the result. Both belong in the (deferred) plugin sandbox, not the engine. Flag as **hype**
  for any "replaces your calibration" claim in a booking context.

### 1.2 LSV calibration

**Current baseline (ANALYTICS-SPEC §5.3):** Heston-QE backbone × Dupire leverage; conditional
expectation E[v|S] by the **particle method (Guyon-Henry-Labordère)**; HV-ADI PDE / Andersen-QE
MC; mixing weight η to broker barrier/touch quotes.

#### (a) Neural / GAN leverage-function calibration — **REJECT for booking**
- **What:** Parametrize the leverage L(S,t) by feed-forward NNs and learn it from market
  prices via deep-hedging variance reduction (Cuchiero–Khosrawi–Teichmann GAN-LSV,
  arXiv:2005.02505 + follow-ups); full-surface calibration in milliseconds; FX-barrier
  two-step deep calibration cutting hours→seconds.
- **Real improvement?** Speed only. The **particle method already calibrates exactly** to
  vanillas (Gyöngyi/Markovian projection is mathematically exact); NN calibration trades a
  reproducible, validatable estimator for a trained surrogate.
- **Deterministic / compliant?** **No.** A trained leverage surface has no QuantLib oracle,
  is non-deterministic to retrain, and is opaque to model validation — disqualifying for the
  booking/Greeks engine.
- **Verdict:** **REJECT** for the engine. Keep the particle method. (Acceptable only as an
  offline *research* tool to sanity-check the particle leverage, never as the booked L.)

#### (b) Control-variate / variance-reduced particle calibration — **ADOPT (as an internal refinement)**
- **What:** The original hybrid-LSV particle papers (e.g. arXiv:1701.06001) add **control
  variates** to the particle estimator of E[v|S] to cut variance and stabilize low-density
  regions / t→0 (exactly the blow-up risk ANALYTICS-SPEC §5.3 calls out).
- **Verdict:** **ADOPT** as a numerical hardening of our existing particle calibrator (it's
  the same deterministic estimator with a variance reducer) — improves stability without
  changing the model or its auditability.

### 1.3 Exotics & advanced dynamics

#### (a) Path-dependent / rough / deep-signature volatility — **DEFER (research lane)**
- **What:** 2025 consensus is shifting. Abi Jaber et al., *"Volatility Models in Practice:
  Rough, Path-Dependent, or Markovian?"* (Mathematical Finance 2025) finds rough-vol
  parameters inconsistent with the global SPX smile shape, favoring **path-dependent (PDV,
  Guyon–Lekeufack)** and tractable **Markovian** approximations. Deep-signature pricers for
  non-Markovian SV (Ma–Wu–Li arXiv:2508.15237, Aug 2025; American/rough via signature kernels
  arXiv:2501.06758, Jan 2025) handle full-path dependence with proven convergence.
- **Real improvement?** Plausibly yes for **forward-smile-sensitive** products (cliquet,
  forward-start, lookback) where even LSV's dynamics are imperfect — this is a known LSV
  weakness, not a solved problem.
- **Deterministic / compliant?** Signature pricers are NN-based ⇒ non-deterministic to retrain
  and hard to validate; PDV itself is a *deterministic SDE* and is the more promising fold-in.
- **Verdict:** **DEFER.** Open a research lane on **PDV as a deterministic model** (it's an
  SDE we can simulate/PDE exactly, like LSV) for forward-smile products; treat deep-signature
  *learning* as offline research only. Nothing booked until QuantLib/published-price
  validation exists. Flag rough-vol-for-everything as **partly hype** given the 2025 evidence.

#### (b) GPU/QMC exotic pricing — see §3.

## 2. Ultra-low-latency systems

**Current baseline (ARCHITECTURE §3):** two-tier — non-async busy-poll core pinned via
`core_affinity` (isolcpus/nohz_full/rcu_nocbs), `rtrb` SPSC, `arc-swap`/`seqlock`/`left_right`
publication, `CachePadded` everywhere, pre-allocated arenas (zero-alloc proven by a counting
allocator), telemetry offloaded to a non-critical core; **tokio** async edge (tonic/prost);
SIMD via autovectorization today, `wide` named as the stable path.

### 2.1 io_uring thread-per-core runtimes (monoio, glommio) — **REJECT (decision stands)**
- **2026 data:** glommio (Datadog, io_uring ≥ 5.8, lockless per-thread rings) and monoio
  (ByteDance) cut median I/O latency roughly in half on I/O-bound workloads (e.g. Apache Iggy
  migration Feb 2026; flashQ Jan 2026 measured 0.4 ms→0.2 ms P50, 312k ops/s). **monoio is
  noted as less actively maintained** (lagging the fast-moving io_uring interface).
- **Critique vs us:** Our **hot core is already not async** — it busy-polls pinned cores and
  never touches a runtime, which is *faster and more jitter-controlled than any io_uring
  reactor* for compute. io_uring would only touch the **control-plane edge**, where we
  deliberately chose tokio for the tonic/axum ecosystem and `Send+Sync` middleware, and where
  ARCHITECTURE §3.1 flags io_uring's **kernel-hardening risk** (disabled in some prod kernels).
  The 2026 numbers (I/O-bound queue throughput) do not describe our edge's bottleneck (gRPC
  control + RFS fan-out, not millions of tiny disk ops).
- **Verdict:** **REJECT / decision stands.** Re-affirm ARCHITECTURE §3.1. Maintenance risk on
  monoio and the security posture both argue against. (Optionally note `tokio-uring` as a
  *future, opt-in* edge experiment gated behind a kernel-capability probe — not a dependency.)

### 2.2 Kernel-bypass NICs (DPDK / Onload / VMA / XDP) — **DEFER (deployment tier)**
- **2026 data:** DPDK/Onload/VMA remain the gold standard for sub-µs tick-to-trade
  (production reports ~850 ns median, <1% loss at 8M pps where io_uring loses 1–5%). io_uring
  trails DPDK on raw packet loss at extreme rates.
- **Critique vs us:** This is a **network-transport** optimization, OS/hardware-specific, and
  **orthogonal to pricing determinism** — it changes how bytes reach `celnet-server`, not how
  we price. It belongs in the deployment/ops tier (kernel-bypass NIC + busy-poll socket), not
  the Rust workspace, and only matters once the *network* is the p99 bottleneck. Our published
  NFRs (2–25 µs pricing) are about compute, not wire.
- **Verdict:** **DEFER** to a deployment ADR; keep `celnet-server` transport-agnostic so a
  kernel-bypass socket can slot under it later. No code change now.

### 2.3 Stable portable SIMD (`wide`) — **ADOPT**
- **2026 state:** `std::simd`/portable_simd is **still nightly** as of May 2026 (no stable
  date). Stable options for FX batch math: **`wide`** (portable, no multiversioning),
  `pulp`/`macerator` (runtime multiversion dispatch). We pin stable 1.96.0, so nightly
  `std::simd` is out.
- **Critique vs us:** ARCHITECTURE §3.4 already names `wide` as the intended escape hatch and
  notes the batch paths are scalar-autovectorized today (~52 ns/option). Explicit `wide`
  vectors give *controlled* lane math (no surprise FMA contraction → preserves determinism)
  for the surface slice arrays and batch payoff — the right SIMD surface.
- **Verdict:** **ADOPT** `wide` (MIT/Apache-2.0) for profiled batch hotspots in
  `celnet-surface` / `celnet-core` batch, gated by a `divan` benchmark proving the win and a
  determinism test proving bit-identity vs the scalar path. Do **not** adopt `pulp`'s runtime
  multiversioning on reproducibility-critical paths (dispatch can pick different lane widths
  per host → cross-platform bit drift). Keep `std::arch` for one-off profiled intrinsics only.

### 2.4 Lock-free / publication primitives — **NO CHANGE (already SOTA)**
- Our `rtrb` SPSC + `arc-swap`/`seqlock`/`left_right` + `CachePadded` stack is exactly the
  2026 best-practice set (Rigtorp-style); nothing surveyed improves on it for our access
  patterns. No change.

### 2.5 Allocator (`mimalloc`/`jemalloc`) — **DEFER (benchmark-gated, as already planned)**
- ARCHITECTURE §3.3 already scopes this as a deferred, benchmark-gated edge-only change (hot
  core is zero-alloc). 2026 brings no new reason to pull it forward. Keep deferred.

## 3. GPU pricing — newest MC / PDE techniques

**Current baseline (ARCHITECTURE §4, ANALYTICS-SPEC §5.4):** `wgpu` 29 + WGSL,
**f32 GPU / f64 CPU reconciliation**, **Philox-4×32-10** counter-based RNG (bit-stable across
backends), integer-atomic / tree reductions; CN+Rannacher and HV-ADI PDEs on CPU.

> **STATUS UPDATE (built since this doc was first written).** The two top recommendations below
> are now **shipped**: **Owen-scrambled Sobol' + Brownian-bridge (§3.1) is built in `celnet-qmc`**
> (`sobol.rs`/`bridge.rs`; measured ≈37.7×/88.5× variance reduction, parity-gated in
> `celnet-parity/tests/qmc.rs`), reused by `celnet-exotics`/`celnet-xva` and by the **`celnet-gpu`
> path (`path.wgsl`) and pathwise/LR Greeks (`greeks.wgsl`) kernels** with a CPU↔GPU Sobol KAT
> (`celnet-parity/tests/{gpu_path,gpu_greeks,qmc_highdim}.rs`). A GPU throughput/latency RATIO
> harness exists (`celnet-bench` `gpu_load`/`gpu_gate` + `gpu_batch` baseline). **Still genuinely
> designed-only:** the GPU PDE path (tiled-stencil/ADI) and the **NVIDIA ABSOLUTE throughput
> headline / ≤50ms exotic** (M4 Metal lacks f64 ⇒ in-repo proves correctness + host-local ratios
> only; absolutes are deploy-gated at G8). The recommendation/verdict prose below is retained for
> design rationale.

### 3.1 Owen-scrambled Sobol' + Brownian-bridge / PCA path construction — **ADOPT (finish the design)**
- **What:** Low-discrepancy Sobol' gives ~O(1/N) vs MC's O(1/√N) on smooth payoffs
  (≈10× fewer paths for smooth integrands); **Owen (nested-uniform) scrambling** restores the
  randomness needed for an honest confidence interval (QMC has no naïve variance estimate) and
  improves high-dimension convergence; **Brownian-bridge or PCA** dimension ordering
  concentrates variance in the first Sobol' dimensions where equidistribution is best
  (well-established; reaffirmed in 2025 HPC-finance / RQMC literature).
- **Critique vs us:** This is the single biggest *correctness-preserving* MC speedup available
  and **we already committed to it in the architecture** — it is currently unbuilt. It cuts
  GPU path counts (and thus the interactive-exotic 50 ms budget headroom) materially.
- **Deterministic?** **Yes**, given a **fixed scramble seed** (Owen scramble seeded from the
  same counter-derived key as Philox). Direction numbers are committed; the bridge is a
  deterministic linear map. This *strengthens* reproducibility vs unseeded RNG.
- **Verdict:** **ADOPT** — implement the `VariateSource::Sobol` path with Brownian-bridge
  construction in `celnet-exotics` (CPU) and `celnet-gpu` (WGSL), swappable behind the
  existing `VariateSource` interface, with the scramble seed part of the deterministic audit
  record. This is the top GPU/MC priority.

### 3.2 Pathwise + Adjoint Algorithmic Differentiation (AAD) for MC Greeks — **ADOPT (selective, hand-written)**
- **What:** Reverse-mode AD computes the **entire** sensitivity vector at ≤ ~4–5× the cost of
  one price (Capriotti; Giles), vs N× for bump-and-revalue — and pathwise/AAD is exact (no
  bump noise). The pathwise method handles smooth payoffs; for discontinuous (digital/barrier)
  payoffs combine with smoothing or **likelihood-ratio/Malliavin** weights. A Rust AAD library
  exists — **`ad-trait`** (arXiv:2504.15976, 2025; first Rust operator-overloading AD with
  both forward+reverse and SIMD forward tangents; integrates nalgebra/ndarray).
- **Critique vs us:** Our exotics Greeks are presumably bump-and-revalue today (N× cost,
  bump-noise-dependent). AAD is a large, exact, deterministic speedup for the LSV/MC Greek
  vector — directly serving the "full Greek set" mandate (ANALYTICS-SPEC §2.1) on exotics.
- **OSS/free?** `ad-trait` licence must be vetted via `cargo-deny` before adoption (advisories
  + licence). **Safer path: hand-write adjoints** for our *fixed, small* kernel set
  (Heston-QE step, leverage application, payoff reductions) — no generic-AD dependency, full
  control over determinism (no FMA contraction, fixed reduction order) and over the
  discontinuous-payoff smoothing choice.
- **Deterministic / compliant?** Yes — analytic adjoints are exact and reproducible; validate
  each adjoint Greek against the existing finite-difference Greek (we already FD-validate all
  14 vanilla Greeks) within ULP/relative tolerance.
- **Verdict:** **ADOPT** hand-written pathwise/AAD adjoints for the exotic MC/PDE Greek
  vector in `celnet-exotics`. Treat `ad-trait` as an *optional* accelerator only if it clears
  `cargo-deny` and a determinism test; do not depend on it for correctness.

### 3.3 Multilevel Monte Carlo (MLMC) — **DEFER (selective, barriers/digitals)**
- **What:** MLMC (Giles) and 2024–25 refinements — variance-reduced MLMC beyond ε⁻²,
  Brownian-bridge + conditional-MC for **barriers/lookbacks**, "multilevel path branching for
  digital options" (Ann. Appl. Prob. 2024) — reduce complexity for the discretization-bias-
  dominated products (barriers, digitals) that are exactly our hard MC cases.
- **Critique vs us:** Real for barrier/digital bias, but MLMC adds estimator complexity and
  its variance/level control must be made deterministic and reference-validated; it composes
  with (does not replace) QMC + BGK/bridge. Lower ROI than §3.1/§3.2 which we already need.
- **Verdict:** **DEFER** — open a follow-up for MLMC on continuously-monitored barriers/
  digitals after Sobol+bridge and AAD land; validate level estimators against the single-level
  + PDE prices. (FPGA-MLMC results, e.g. arXiv:2502.07123, are noted but out of scope — no
  commercial FPGA toolchains, CLAUDE.md rule 7.)

### 3.4 GPU PDE (tiled ADI / cyclic-reduction tridiagonal) — **ADOPT (finish the design)**
- ARCHITECTURE §4 already designs GPU ADI as tiled stencils + PCR/cyclic-reduction tridiagonal
  solvers (the production CN+Rannacher / HV-ADI run on CPU today). No newer technique surveyed
  beats this for our 1D/2D LSV grids; the work is *implementation*, validated against the CPU
  PDE and MC. **ADOPT** as planned (after the MC QMC work, which has broader payoff).

### 3.5 Tensor-core / low-precision MC — **REJECT for pricing math**
- Tensor-core / FP16/BF16 acceleration is irrelevant-to-harmful for FX-options pricing
  accuracy (we already standardize **f32 GPU with f64 CPU reconciliation** precisely because
  even f32 needs bounding). Lower precision would widen the reconciliation gap beyond
  tolerance. **REJECT** for the numeric path. (Hype for our use case.)

## 4. Determinism / reproducibility & numerical methods

**Current baseline (ARCHITECTURE §8):** `rust-lang/libm` (correctly-rounded ≤ 1 ULP),
forbid FMA contraction / fast-math on reproducible paths, centralized `is_close`/`assert_close`
(ULP+rel+abs), no `==`/NaN-bit asserts, pinned toolchain, committed proptest-regressions +
fuzz corpora, QuantLib 1.42.1 golden tables, financial-invariant property tests, `insta`
snapshots, `cargo-mutants`, `cargo-llvm-cov`.

### 4.1 Assessment — **NO CHANGE; baseline is already SOTA**
- This is *exactly* the 2026 best-practice reproducible-numerics stack. The `libm` correct-
  rounding + no-FMA + centralized-tolerance discipline is what every method above must respect.
  Nothing surveyed improves it. **No change** — but it is the **gating filter**: it is the
  reason every NN method in §1 is deferred/rejected for booking and every QMC/AAD method is
  adopted with a fixed-seed + reference-validation requirement.

### 4.2 Reinforcing notes for the adopt-list
- **Owen-scramble seed and Sobol' direction numbers** become part of the committed
  deterministic audit record (treat like the proptest seeds / golden tables).
- **AAD adjoints** must use the same fixed reduction order / no-FMA policy as the primal, and
  each adjoint Greek is golden-validated against finite difference — adding a *new* invariant
  class to `celnet-testkit` (adjoint-vs-FD consistency), not weakening any.
- **`wide` SIMD** paths require a bit-identity test vs the scalar path on every supported arch
  (the only acceptable SIMD-determinism proof).
