## Celnet — Optimal Integrated Architecture (Chief-Architect Determination)

### 1. Current shape (synthesized across all five dimensions)

Celnet is a **40-crate, strictly one-way Cargo workspace** (the doc says 39; `celnet-rates` is real-but-undocumented on disk). The real build DAG is genuinely acyclic — `celnet-types` (dependency-free root) ← `celnet-core` ← the analytics/leaf tier ← `celnet-engine`/`celnet-server`, ~9 levels deep — with two apparent cycles (`client↔server`, `surface↔crypto-vanilla`) that are dev-dependency-only back-edges Cargo permits. The interface waist is minimal and correct: `celnet-proto` build-depends ONLY on `celnet-types`; `celnet-plugin-api` on `types`+`core`.

Four **load-bearing seams** are in place and, where they exist, proven:

- **Carry seam (ADR-0008)** — the structural spine. `celnet-core::carry::CarryInputs` exposes exactly `forward(t)` and `CarryInputs.discount_df(t)`; `celnet-types::Carry` (`FxRates{r_dom,r_for}` | `CostOfCarry{r,b}`) collapses both to `F=S·e^{b·t}`, `df=e^{−r·t}`. The FX path is **byte-identical** to the pre-seam `VanillaInputs` (gated by `fx_carry_inputs_byte_identical` and `forward_and_df_match_core_carry_inputs_byte_for_byte`). Five leaf crates ride it (vanilla/crypto/commodity/equity/linear) as true `core`/`types`-only leaves. The only `match carry` sites are the off-hot-path **sensitivity-routing** layer (ADR-0008's explicit carve-out), not pricing math.
- **One unversioned contract (ADR-0007/#9)** — `celnet-proto` carries additive oneofs defaulting to FX, no `schema_version`. The entitlement principal is mirrored field-for-field across proto → gRPC → WS-JSON → SDK → GUI → Excel, every client asserting explicit `grant_all` (`Principal.grant_all` / `principal_or_grant_all` / `principalOrGrantAllToWire`).
- **Hot-core / async-edge split** — `celnet-fanout` SPMC seqlock ring carries Copy/POD `PriceTick`/`PriceRequest`/`PriceResponse`; `celnet-engine` takes no telemetry dependency; `celnet-observability` owns all rings/histograms. Conflation is exact (`received+skipped==produced`, gated to 1000 consumers).
- **Tiered plugin host** — `celnet-plugin-host::ModelRegistry` dispatches `NativeModel` (Tier-0) and `WasmModel` (Tier-2 wasmi) behind the **same** `PricingModel`/`CarryInputs` seam.

The de-facto module structure (Leiden over 21,340 nodes / 64,346 edges) largely tracks the crate families (calendar/conventions 0.88, proto-decoders 0.91, replicated-risk-state 0.80), and the highest-fan-in nodes are healthy leaf primitives, not god-objects. Real cross-process risk federation **exists and is tested** (`Fleet.connect_with_membership` + `federate.fan_out` over loopback gRPC with failover), exceeding what the docs admit.

**But the seams do not all reach the same depth, and the doc-vs-reality drift is real.** Three asymmetries dominate: (a) the carry seam stops at the request/leaf layer and does **not** reach the streamed hot edge (`pair_seed(&CcyPair)` + `MarketContext.fx(...)` are FX-only; the wire `Update` carries the two-rho `Greeks`, not the carry-tagged `RateSensitivities` oneof the contract already defines); (b) the access gate is **not a cross-cut** — `resolve_caller`+`authorize_caller` are hand-copied into ~10 handlers, with the stream/execute path and the entire WS mirror ungated; (c) four built crates (`celnet-plugin-host`, `celnet-rates`, `celnet-xva`, `celnet-replog`) are **unwired into the runtime** — the plugin host the docs call "built" is never loaded by the server.

### 2. Target architecture

**Layering (keep the skeleton, close the drift).** A strictly one-way DAG where **every built crate is either wired to a runtime consumer or explicitly tagged deferred in INTERFACES.md**. Keep the minimal `types`/`proto`/`plugin-api` waist and mechanically gate it (cargo-deny ban-dep so `proto` can never grow a non-`types` build edge and the `match carry` ban holds). Demote `celnet-risk-cube`'s heavyweight `exotics`/`gpu` edges to an injected `RepriceFn` trait so the OLAP layer depends on an abstraction, restoring it to a pure aggregation layer and shrinking its rebuild blast radius. Drop the two dev-dep back-edges by relocating shared fixtures into `celnet-testkit`.

**The carry seam reaches end-to-end.** This is the single highest-leverage target. The same `forward(t)`/`discount_df(t)` abstraction that makes "add an asset class = new `Carry` builder, zero payoff edits" true for **batch pricing** must hold for **streaming, registries, and sensitivities**:
- Replace `pair_seed(&CcyPair)` + `MarketContext.fx(...)` with an **Underlying-keyed, carry-tagged** tick; change wire `Update` to carry the `RateSensitivities` oneof alongside/instead of the fixed two-rho `Greeks` — keeping `PriceTick` Copy/POD via a fixed-shape carry-tagged risk strip. Then a crypto/equity option streams as a first-class non-FX line with zero further edits.
- Give Equity/Commodity/DigitalAsset a **registry home**: an Underlying-keyed convention/calendar/surface lookup so they stop bottoming out at `as_ccy_pair → None` (this also unblocks the open R8 crypto strike-axis surfacing fast-follow).
- Collapse the per-exotic `match i.carry => RateSensitivities` duplication into **one shared carry→sensitivity mapper** in `celnet-core`, so a third `Carry` arm is a single edit.

**The product router becomes a structural module.** `celnet-server::pricer::price_instrument` is a **1207-line god-function** (complexity 154, in_degree 62 / out_degree 111) fanning to ~50 routines — the de-facto "product-dispatch module" with no home. Replace the central match with a `ProductEngine` registry/trait (price+greeks over the carry seam), one impl per family, so `price_instrument` shrinks to decode→lookup→dispatch (<100 lines) and "add a product" becomes "register an impl" — mirroring the carry seam's already-won pattern and removing the top merge-conflict seam.

**Cross-cuts enforced once, at the lowest layer that spans every transport, failing closed.**
- **Access**: replace the 10 hand-copied `resolve_caller`+`authorize_caller` pairs with a single tonic `Interceptor`/`tower::Layer` reading a static `&[(rpc_path, RequiredAuthority)]` registry, with an equivalent WS-frame guard at `ws::mod::handle_unary`. Unlisted RPC defaults to **deny**. Gate the stream/execute path (`handle_subscribe`/`handle_execute`) — execute is an action, not a read.
- **Errors**: make `celnet-observability::ErrorClass` the single source, `impl From<ErrorClass> for tonic::Status`, derive the WS code from the same mapping, round-trip tested.
- **Observability**: unchanged — it is the exemplar (hot core dependency-free, telemetry/audit split). Keep the entitlement principal mirroring as the template for every cross-cutting wire concern.

**Integration & scale-out: one contract, one generator, N transports.** The partition (HRW by pair/tenant via `celnet-router`) and the additive/non-additive merge algebra (`NodeAggregate::merge_additive` for sums; bump-and-revalue for VaR/ES) are the **correct, bit-identically-proven shard boundary** — the fleet scales horizontally as designed. The binding constraints are not the algebra:
- Apply ADR-0009's "one generator, two projections / drift fails CI" discipline to the **existing** hand-maintained `ws/codec.rs` (`product_from_json` + 253 `*_from_json` round-trips kept in lockstep only by 253 hand-written tests) — generate the WS projection from `celnet-proto` so a new arm cannot compile without it.
- Build ADR-0009 `EdgeFrame` behind transport-negotiation-at-handshake (Phase 0–2 are in-repo gatable), removing per-tick prost/JSON cost from the HFT line — but do the carry-tagged stream FIRST, since EdgeFrame must project the generalized `Update`.
- Promote the **Celer ingress decision** (JVM-adapter-sidecar vs `DistributorProducerChannelHandler` socket) to an ADR and terminate `celnet-integration::egress` in a committed transport trait — the single largest open integration boundary.
- Extend risk-fact coverage beyond vanilla-only (`services::risk::store`) so the federated cube covers the exotic/cross-asset book the platform actually prices.

### 3. Prioritized refactors / risks (highest-leverage first)

1. **Extend the carry seam to the streamed edge** (highest leverage; unlocks cross-asset live quoting). Replace `pricefanout::pair_seed`/`MarketContext.fx` with an Underlying-keyed carry-tagged tick and move wire `Update` to the `RateSensitivities` oneof. *Anchors: `celnet-server.src.services.pricefanout.pair_seed`, `celnet-proto.src.helpers.MarketContext.fx`, `celnet-core.src.carry.CarryInputs.discount_df`.*
2. **Make the access gate a real cross-cut, fail-closed** (security-by-omission risk: stream/execute + entire WS mirror currently ungated). Single interceptor + WS guard + per-RPC authority table. *Anchors: `celnet-server.src.services.access.authorize_caller`, `.resolve_caller`, `celnet-server.src.ws.mod.handle_unary`.*
3. **Dissolve the `price_instrument` god-function into a `ProductEngine` registry** (top merge-conflict/churn seam; unit-testability). *Anchor: `celnet-server.src.pricer.price_instrument`.*
4. **Resolve the four dormant crates**: wire `celnet-plugin-host` into the server registry (make "built" true), wire `xva`/`replog` to a server path, land `celnet-rates` behind the `forward()/discount()` seam — or explicitly tag each deferred in INTERFACES.md. *Anchors: `celnet-plugin-host.src.registry.ModelRegistry.register_native`, `celnet-server.src.pricer.price_instrument`.*
5. **Generate the WS codec from proto** (retire the 253 hand-written drift guards). *Anchor: `celnet-server.src.ws.codec.product_from_json`.*
6. **Decouple `risk-cube` from `exotics`/`gpu` via an injected `RepriceFn`**; restore pure-aggregation layering. *Anchor: `celnet-entitlements.src.filter.EntitlementFilter.entitled_cube` (the aggregation boundary risk-cube feeds).*
7. **Reconcile docs to built reality** (federation transport IS built; crate count 40; `risk-normalize` cross-asset deps; line 63). *Anchors: `celnet-server.src.services.risk.federate.Fleet.connect_with_membership`, `.fan_out`.*
8. **Unify the error taxonomy** (`From<ErrorClass> for tonic::Status` + WS derive). *Anchor: `celnet-server.src.services.access.authorize_caller` (Status-building sites).*
9. **Collapse duplicated sensitivity-routing** into one shared carry→sensitivity mapper in `celnet-core`. *Anchor: `celnet-core.src.carry.CarryInputs.discount_df`.*
10. **Resolve the Celer ingress ADR + extend risk facts to exotics/cross-asset** (the deploy-boundary + risk-coverage gaps). *Anchors: `celnet-risk-fleet.src.lib.fan_out_aggregate`, `celnet-server.src.services.risk.federate.fan_out`.*
11. **Drive a restrictive principal through ≥1 client e2e under Enforce** (close the deferred-e2e client-side blind spot). *Anchor: `celnet-entitlements.src.principal.Principal.grant_all`.*

## Appendix — dimensional analyses (evidence base)

### layering-deps (crate layering & dependency structure)

**Current state:** The workspace is a flat 40-crate Cargo set (INTERFACES.md §"The 39-crate workspace" undercounts by one — `celnet-rates` is real on disk but undocumented). I extracted the actual `[dependencies]` edges from every `crates/*/Cargo.toml` rather than trusting the doc. The runtime build DAG is genuinely acyclic and one-way: `celnet-types` (zero deps) ← `celnet-core` (← types only) ← the analytics/leaf tier ← `celnet-engine` ← `celnet-server`. Longest normal-dep chain runs ~9 levels deep (types→…→risk-cube→risk-fleet/entitlements→server; `celnet-bench`/`-cli` sit above as build sinks). The three load-bearing interface crates are confirmed minimal and correctly placed: `celnet-proto` depends ONLY on `celnet-types` for the build (its `celnet-core` edge is dev-dependency only — INTERFACES.md line 52 is accurate); `celnet-plugin-api` depends on `celnet-types`+`celnet-core` (matches line 53); `celnet-types` is a true root with no internal deps. The carry seam (ADR-0008) is the structural spine: `Underlying` identity / `Carry` forward-discount producer / asset-agnostic payoff engines, with the binding "no-workaround test" that payoff code calls `inputs.forward(t)`/`inputs.discount_df(t)` and never `match carry {…}`. Two apparent cycles — `celnet-server`↔`celnet-client` and `celnet-surface`↔`celnet-crypto-vanilla` — are DEV-dependency-only back-edges (client's `celnet-server` is under `[dev-dependencies]` line 23; surface's `celnet-crypto-vanilla` under `[dev-dependencies]` line 26), which Cargo permits and which do not form a real compile cycle. get_architecture reports 21,340 nodes / 64,346 edges with Leiden clusters that cut across the folder layout along call seams (cluster 29 `price_instrument`/`conv_set`/`r_dom`/`r_for` cohesion 0.80 = the FX pricing core; cluster 14 `firm_aggregate`/`ReplicaId`/`BookId` cohesion 0.80 = the risk/replication estate; cluster 0 `date`/`pair`/`normalize`/`weekday` cohesion 0.88 = the conventions/calendar leaf).

**Strengths:**
- Dependency direction is genuinely one-way and acyclic in the real build graph. `celnet-types` is a dependency-free root; `celnet-core` depends only on types; every analytics/leaf crate fans in below `celnet-engine`/`celnet-server`. No normal-dependency cycle exists across all 40 crates.
- The three interface crates are minimal and correctly load-bearing. Verified from Cargo.toml: `celnet-proto` build-depends ONLY on `celnet-types` (core is dev-only), `celnet-plugin-api` on `celnet-types`+`celnet-core`. This keeps the wire contract and plugin SDK at the narrow waist INTERFACES.md promises, so a leaf change never forces a proto rebuild.
- The carry-seam layering (ADR-0008) is a strong, enforced abstraction: identity/`Underlying` ← market/`Carry` (forward+discount producer) ← agnostic payoff engines, with a binding review-blocker rule against `match carry{…}` in payoff code and an FX byte-identity invariant (`Carry::FxRates` reproduces GK forward/discount bit-for-bit). A new asset class is an additive `Carry`/`MarketState` builder with zero payoff-engine edits — confirmed by `celnet-equity-vanilla`/`-commodity-vanilla`/`-crypto-vanilla` each depending only on `-core`/`-types` (true leaves).
- The big consolidations are dependency-sound: `celnet-surface` (VV/SABR/SVI/SSVI/eSSVI) and `celnet-exotics` (LSV+PDE+MC+basket+numerics) sit cleanly between the vanilla tier and the engine. `celnet-fanout` and `celnet-observability` are zero-internal-dep leaves, keeping the hot core free of telemetry deps as required by guardrail #11.
- The risk estate layers correctly bottom-up: `risk-normalize` (canonical leaf) ← `risk-cube` (OLAP) ← `limits`/`entitlements`/`risk-fleet`, each documented as a pure no-IO transform, which makes a roll-up a plain group-by+sum above the normalize boundary.

**Risks:**
- FOUR built crates are unwired into the runtime — a 'designed-and-validated but not integrated' reservoir. From Cargo in-edge analysis: `celnet-plugin-host` (wasmi Tier-2 sandbox) and `celnet-rates` have ZERO references from ANY crate; `celnet-xva` and `celnet-replog` are referenced ONLY by `celnet-parity` (the validation crate), never by `celnet-server`. So the plugin host that INTERFACES.md calls 'built' (line 41/99) is not actually loaded by the server, and XVA/leader-replicated-replog never reach the wire. This is real-but-dormant code, not dead, but it is layering debt: the integration edge is missing.
- `celnet-rates` (1409 LOC: bootstrap.rs/curve.rs/ois.rs/risk.rs/solver.rs) is a fully orphan crate — zero in-edges AND absent from INTERFACES.md's crate inventory (which claims 39; disk has 40). This is the deferred `celnet-curve` from ADR-0008 §Forward-compatibility, built ahead of its seam, undocumented and unwired. It is the clearest doc-vs-reality drift in the layering.
- INTERFACES.md line 63 is STALE: it declares `celnet-risk-normalize` a 'pure leaf transform over celnet-vanilla/-core/-types (no IO)', but its actual `[dependencies]` now include `celnet-equity-vanilla`, `celnet-commodity-vanilla`, AND `celnet-crypto-vanilla` (non-dev). The crate grew cross-asset reach to canonicalize mixed-asset risk; the frozen-interface registry was not updated in lockstep, violating guardrail #10 (docs in sync).
- `celnet-risk-cube` non-dev-depends on `celnet-exotics` AND `celnet-gpu` (comments: exotics so exotic positions aren't silently excluded from roll-ups, gpu for a closed form). This pulls the heavyweight numerics+GPU subtree into the risk-aggregation layer, inflating the risk-cube build/rebuild blast radius and coupling the OLAP layer to PDE/MC/wgpu — a layering smell for a crate documented as a pure aggregation engine. `risk-cube` already sits at ~depth-9; this widens its rebuild cost against the T0/T1 'rebuild a minimal subtree' goal.
- `celnet-parity` is a god-dependency: it depends on ~23 internal crates (almost the entire graph: every leaf, risk, replog, xva, router, gpu). As the cross-asset oracle that is by design, but it means any leaf change can trigger a parity rebuild, and it is the ONLY consumer keeping xva/replog from being formally orphan — masking their lack of runtime integration behind a green test crate.
- Dev-dependency back-edges (`client`→`server`, `surface`→`crypto-vanilla`) are legal but create a maintenance trap: the surface crate reaching into a crypto leaf even for tests inverts the intended 'leaves consumed only by the server' rule (INTERFACES.md line 83), and `client`→`server` dev-dep means the SDK's test build pulls the entire server tree.

**Optimal:** Target shape: a strictly one-way DAG where every BUILT crate is either (a) wired to a runtime consumer or (b) explicitly tagged deferred in INTERFACES.md, with the interface waist (`types`/`proto`/`plugin-api`) kept minimal. Concrete moves: (1) Resolve the four dormant crates — either wire `celnet-plugin-host` into `celnet-server`'s registry (make the 'built' claim true end-to-end), and wire `celnet-xva`/`celnet-replog` to a server RPC/loopback path, OR move them under an explicit `[workspace] deferred` section in INTERFACES.md with the integration edge named as the open deliverable. Do the same for `celnet-rates`: either land it behind the `forward()/discount()` seam as ADR-0008 promised (`Carry` flat-rate degenerate → curve), or document it as deferred and add it to the crate inventory. (2) Fix the INTERFACES.md drift NOW (guardrail #10): correct the count to 40, list `celnet-rates`, and rewrite line 63 to reflect that `risk-normalize` depends on the three cross-asset leaves. (3) Re-examine `risk-cube`→`exotics`/`gpu`: extract the 'reprice exotic/closed-form for a node' capability into a thin `RepriceFn`/trait injected by the server, so `risk-cube` depends on an abstraction, not on the PDE/MC/wgpu subtree — restoring it to a pure aggregation layer and shrinking its rebuild blast radius. (4) Drop the `client`→`server` and `surface`→`crypto-vanilla` dev-dep back-edges by moving the shared test fixtures into `celnet-testkit` (already a leaf both can depend on downward), eliminating the inverted edges. (5) Keep enforcing the ADR-0008 no-`match carry` rule and the `proto`-depends-only-on-`types` waist via a cargo-deny/ban-dep lint so the one-way invariant is mechanically gated, not just documented.

### core-seams

**Current state:** Five load-bearing seams, grounded in graph + ADRs + verified knowledge:

(1) CARRY SEAM (ADR-0008, Accepted 2026-06-08) is REAL and correctly placed. `celnet-core::carry::CarryInputs` exposes exactly two payoff-facing methods — `forward(&self) = spot * carry.forward_factor(t)` (carry.rs:76) and `discount_df(&self) = carry.discount_df(t)` (carry.rs:85). The `Carry` enum (celnet-types/src/lib.rs:919) has two arms: `FxRates{r_dom,r_for}` and `CostOfCarry{r,b}`, both collapsing to `F=S·e^{b·t}`, `df=e^{−r·t}`. Verified claim cl_a94fa19d311a6131 (groundedness 1.0): the FX path is byte-identical to `VanillaInputs::forward` (proved by `fx_carry_inputs_byte_identical`). The plugin seam was generalized in place: `PricingModel::price(&self, opt, inputs: &CarryInputs)` (celnet-plugin-api/src/pricing.rs:66) — the ADR-0008 'old' FX-only `price(OptionType,&VanillaInputs)` seam is gone, not shimmed. `Underlying` (lib.rs:410) is a clean additive discriminated union: Fx/Metal/Equity/Commodity/DigitalAsset, each with `as_*` projection accessors; non-pair arms return None from `as_ccy_pair` rather than coercing. Five real leaf crates ride the seam: celnet-vanilla (FX), celnet-crypto-vanilla (linear+inverse), celnet-commodity-vanilla (Black-76), celnet-equity-vanilla, celnet-linear, each with its own `cost_of_carry`.

(2) ONE UNVERSIONED CONTRACT (ADR-0007, Accepted) is enforced structurally. proto/celnet.proto carries additive oneofs — `Underlying.ref` (line 390), `CarryModel.model` (505), `RateSensitivities.sensitivities` (519) — all defaulting to FX, no `schema_version` anywhere. `Update` (1883) carries seq + TwoWayPrice + Greeks + repeated TradableToken click-to-trade tokens.

(3) HOT-CORE / ASYNC-EDGE SPLIT is real and zero-alloc. `celnet-fanout::ring::Producer<T>::publish(&mut self, item: T)` (ring.rs:155) is a single-producer seqlock SPMC writer — odd/even stamp straddles the payload write, no alloc, no branch, generic over a Copy `T`. The core↔edge rings carry `PriceRequest`/`PriceResponse`/`PriceTick` (all Copy/POD), NOT the Clone-not-Copy `CarryInputs`.

(4) HAND-OFF CODEC (ADR-0009) is PROPOSED, NOT BUILT. search_graph for EdgeFrame/EdgeQuote/wire_edge returns exactly ONE node: the ADR doc section itself (in_degree 0). No `celnet-wire-edge` crate exists. The streamed edge still serializes via prost/JSON.

(5) TIERED PLUGIN HOST is real: `PricingModel` trait (plugin-api) implemented by `NativeModel` (Tier-0) and `WasmModel` (Tier-2 wasmi sandbox), dispatched via `HostModel`/`ModelRegistry` (celnet-plugin-host).

**Strengths:**
- Carry seam passes its own no-workaround test where it counts. The only `match i.carry` sites in payoff crates (american.rs:287, perpetual.rs:457) are in the RATE-SENSITIVITY routing layer — deciding which factors to bump for risk reporting (FX bumps r_dom/r_for natively, CostOfCarry bumps r,b) — with an explicit anchored comment 'the per-node hot path (the PSOR sweeps inside each price call) never dispatches on Carry' (american.rs:283). Pricing math reads only forward(t)/discount_df(t). This is exactly the ADR-0008 carve-out, not a violation.
- Byte-identity is gated, not asserted. `forward_and_df_match_core_carry_inputs_byte_for_byte` (celnet-linear), `context_forward_is_carry_seam_bits` (celnet-surface), `fx_carry_inputs_byte_identical`, and verified claim cl_a94fa19d311a6131 (groundedness 1.0) lock the FX path bit-for-bit — the proof the seam was inserted UNDER FX without perturbing it.
- Zero-alloc hot core is structurally protected from the cross-asset generalization. CarryInputs is deliberately Clone-not-Copy (Underlying carries string-bearing Equity/Commodity/DigitalAsset Ref arms), but it never touches the SPMC ring: PriceTick/PriceRequest/PriceResponse are the POD ring payloads. The Greeks POD on the hot ring keeps its fixed two-rho shape; the allocating FRTB factor decomposition is pushed off-path to celnet-risk-cube. The 'general vs zero-alloc' tension is resolved by layering, not compromise.
- Unversioned contract is genuinely additive — a new asset class is new oneof arms with FX defaults, so every existing ticket / CELNET.PRICE / `celnet price EURUSD` is unchanged (validated by the W0 conformance corpus across 5 clients with to_bits equality). ADR-0007/0008/0009 are explicitly cross-referenced and mutually consistent (content tags not version tags).
- Forward-compat seam-placement test is real: a flat-rate Carry is the degenerate single-point curve, so the P1 celnet-curve (OIS/CSA) slots behind the same forward()/discount() with zero payoff edits. Multi-curve readiness is designed in, not retrofitted.
- Plugin host correctly isolates untrusted extension behind the SAME PricingModel/CarryInputs seam the native leaves use — WasmModel (wasmi, fuel-metered) and NativeModel are interchangeable to the registry, and a guest prices on the generalized carry input (equity_cost_of_carry_model_reconciles_to_independent_oracle gates a wasm guest against an external oracle).

**Risks:**
- STREAMING EDGE IS STILL FX-SHAPED — the carry seam stops at the request/leaf layer and does NOT reach the hot fan-out. The producer builds `PriceTick.market` via `MarketContext::fx(0,0,0,0)` (pricefanout.rs:109) and keys subscriptions on `CcyPair` via `pair_seed(&CcyPair)` (pricefanout.rs:121). Worse, the wire `Update.greeks` field (proto line 1891) is the FX-shaped two-rho `Greeks`, NOT the carry-tagged `RateSensitivities` oneof that the rest of the contract added. So a crypto/equity option can be PRICED through CarryInputs but cannot STREAM as a first-class non-FX tick with its own discount/carry rho — the cross-asset abstraction is request-path-only. A new asset class plugs into pricing with zero edits but forces edits to stream/fanout/PriceTick to actually quote live. This is the single biggest seam-placement asymmetry.
- ADR-0009 hand-off codec is PROPOSED and UNBUILT — search_graph confirms zero `celnet-wire-edge`/`EdgeFrame` code nodes (only the ADR section, in_degree 0). The 'one generator, two projections' build-time consistency gate that would keep EdgeFrame == proto Update projection (ADR-0009 §2.2) does not exist yet, so the claimed drift-protection for the second encoding is aspirational. The high-volume edge still pays per-tick prost/JSON varint cost the ADR identifies as the next-largest tail-latency contributor — the seam is designed but the gap is open.
- Underlying↔registry bridge is a coercion seam with silent narrowing. `as_ccy_pair` (lib.rs:492) projects Fx and Metal onto a CcyPair the convention/calendar registries key on, but Equity/Commodity/DigitalAsset return None — meaning the convention/calendar/surface registries are still CcyPair-keyed and the three string-bearing asset classes have NO registry home. A new equity/commodity payoff that needs calendar or convention resolution hits a None and must either special-case or be blocked. The identity layer generalized ahead of the registries it feeds.
- CarryModel proto oneof has only TWO arms (FxRates, generalized CostOfCarry) collapsing every non-FX class to a single net `b` (proto line 505, lib.rs Carry). ADR-0008 itself flags this as lossy for risk ('cannot independently report dividend-rho vs convenience-rho from one b') and accepts it. For a true cross-asset risk cube that needs equity-dividend vs commodity-convenience as DISTINCT factors, the two-arm Carry under-models — the factor split lives only at the off-path risk layer, so the streamed/wire risk view cannot distinguish them.
- Crypto strike-axis surfacing is an explicitly open seam (CLAUDE.md resume anchor: R8-surfacing operator-re-scoped to the first post-RC fast-follow surface/crypto-strike-axis-surfacing). The DigitalAsset arm can price but its strike-axis quote ingestion into the surface seam is not wired — so the newest asset class is NOT yet symmetric with FX at the surface boundary.
- Sensitivity-routing match-on-carry is duplicated per exotic (american.rs, perpetual.rs each carry their own `match i.carry => RateSensitivities` block). It is legitimate per ADR-0008, but it is copy-paste structural debt: adding a third Carry arm forces edits in every exotic's sensitivity block rather than one shared carry-to-sensitivity mapper. The seam abstracts pricing but NOT sensitivity-axis selection.

**Optimal:** Target shape: the carry seam should reach all the way to the streamed edge, the registries the identity layer feeds, and a single shared sensitivity mapper — so 'new asset class = zero edits' holds end-to-end, not just at the pricing leaf.

Concrete moves:
1) CLOSE THE STREAMING ASYMMETRY (highest leverage). Replace the FX-only `PriceTick.market = MarketContext::fx(...)` and `pair_seed(&CcyPair)` keying with an Underlying-keyed tick whose market context is carry-tagged, and change wire `Update` to carry the `RateSensitivities` oneof (already in the contract at proto line 519) instead of / alongside the fixed two-rho `Greeks` (line 1891). Keep the ring payload Copy/POD by giving PriceTick a fixed-shape carry-tagged risk strip (the RateSensitivities enum is already Copy-able — it is FxRho|CarryRho, no allocation). This makes a crypto/equity option stream as a first-class non-FX line with zero further edits.

2) BUILD ADR-0009 or formally defer it. It is PROPOSED with zero code; either claim the `celnet-wire-edge` lane and land Phase 0 (EdgeFrame layout + the proto-projection consistency gate that prevents the two-encoding drift the ADR's own §4 lists as the top risk), or move ADR-0009 to a deferred register so the architecture doesn't imply a fast edge that isn't there. Do step 1 FIRST — EdgeFrame must project the carry-tagged Update, so generalizing the stream is a prerequisite.

3) GIVE THE THREE STRING-BEARING ASSET CLASSES A REGISTRY HOME. Introduce an Underlying-keyed (not CcyPair-keyed) convention/calendar/surface lookup so Equity/Commodity/DigitalAsset stop bottoming out at `as_ccy_pair → None`. This is the registry-side mirror of the ADR-0008 identity generalization and unblocks crypto strike-axis surfacing (the open R8 fast-follow).

4) COLLAPSE THE DUPLICATED SENSITIVITY-ROUTING. Extract the per-exotic `match i.carry => RateSensitivities` blocks (american.rs:287, perpetual.rs:457, …) into ONE shared carry→sensitivity-bump mapper in celnet-core, so a third Carry arm is a single edit. The pricing seam is clean; make the sensitivity seam equally single-edit.

5) RE-EXAMINE the two-arm CarryModel for cross-asset risk. The net-`b` collapse is fine for forward/discount math but blocks distinct dividend-rho vs convenience-rho on the wire. Decide explicitly: either keep the factor split strictly off-path in risk-cube (document it as the contract's accepted limit) or widen CarryModel when the first client needs streamed asset-class-distinct rate Greeks — do not let it drift unstated.

Net: the carry/contract/host seams are placed correctly and proven byte-identical on FX; the work left is to extend the SAME seam through the streaming edge, the registries, and the sensitivity mapper so the 'plug in with zero edits' promise is true for streaming and surfacing, not only for batch pricing.

### cross-cutting concerns — entitlements (deny-by-default), observability (zero-cost telemetry), error handling, and the one wire contract — across server / client SDK / WS-JSON / GUI / Excel

**Current state:** The four cross-cuts sit at very different maturity levels.

ENTITLEMENTS exist as a clean two-layer model but are enforced inconsistently. There are TWO distinct mechanisms: (1) a coarse access GATE — `celnet-server.src.services.access.authorize` / `authorize_caller` (access.rs), which is deny-by-default in `AccessMode::Enforce` (absent principal → `Status::unauthenticated`, "denied by default") and grant-all in `Permissive`; (2) a fine-grained PRUNING FILTER — `celnet-entitlements` `Principal::{grant_all,scoped,grant,deny}` + `EntitlementFilter::entitled_cube`, deny-wins, applied pre-aggregation inside `RiskEdge.aggregate_risk_impl` (risk/mod.rs). The graph shows the GATE is invoked ONLY from `risk/mod.rs` (4 handler methods, lines 699-782) and `fix_admin.rs` (6 methods, lines 135-310) — via a HAND-COPIED `resolve_caller(...) + authorize_caller(...)` pair repeated in every handler. There is NO tonic interceptor / tower::Layer (grep for Interceptor/ServiceBuilder/layer returns nothing). Critically, `stream.rs` (the price/subscribe/execute hot-path Session service) and `pricefanout.rs` call `authorize`/`resolve_caller` ZERO times, and the WS mirror (`ws/mod.rs`, `ws/codec.rs`) has zero `authorize`/`resolve_caller` references — those paths are not access-gated at all; they rely solely on the pruning filter (which prunes risk facts, not subscribe/execute capability).

WIRE CONTRACT is the strongest cross-cut. ADR-0007 establishes one unversioned contract evolved in place (no schema_version, additive oneofs default-to-FX per ADR-0008), and the entitlement principal is mirrored uniformly end-to-end: proto `EntitlementPrincipal{grant_all,grants,denies}` → gRPC handler `convert::principal_of` → WS-JSON `ws/codec.rs entitlement_rule_from_json`/`risk_scope_from_json` → SDK `celnet-client.src.risk.principal_or_grant_all` → GUI `contract.ts principalOrGrantAllToWire` → Excel. Every client applies the SAME explicit grant-all default (the Round-4 P1 fix: omitted principal is encoded as explicit grant_all so a client's show-all posture survives the server's Enforce default-flip), documented identically in gui/src/data/contract.ts:1460-1467.

OBSERVABILITY is correctly layered at the crate boundary: `celnet-observability` owns the POD `PriceSample`/`ErrorClass` records, the rtrb rings, the drain, HdrHistograms and the `metrics` facade; `celnet-engine` (hot core) takes no tracing/metrics dependency (OBSERVABILITY.md §7), proven by `tests/zero_alloc.rs`. Telemetry (lossy/drop-on-full) and audit (lossless/back-pressured/fsync) use separate rings (§6).

ERROR HANDLING is split into two unbridged vocabularies. `celnet-observability` defines a `#[repr(u16)] ErrorClass` (Ok/InvalidInput/StaleState/NoConvergence/Arbitrage/TelemetryDropped/Internal, record.rs:96) with `LogClass::from_error_class`. The edge maps errors via `tonic::Status` independently — WS `ws/mod.rs status_error` just stringifies `status.code()` with `format!("{:?}")`. Grep confirms `celnet-server` depends on `celnet-observability` (Cargo.toml:39) but references `ErrorClass` ZERO times.

**Strengths:**
- Wire-contract uniformity is real and verified: the entitlement principal + scope types are mirrored identically across proto → gRPC → WS-JSON (entitlement_rule_from_json) → SDK (principal_or_grant_all) → GUI (principalOrGrantAllToWire) → Excel, with the SAME explicit grant-all default at every client. ADR-0007's one-unversioned-contract is honored — no schema_version anywhere, additive oneofs default-to-FX (ADR-0008).
- Entitlement semantics are sound and centralized in ONE owning crate: `celnet-entitlements` holds deny-wins, scoped()=deny-by-default, and the pruning predicate; pruning runs PRE-aggregation in aggregate_risk_impl so a sub-tree never leaks into a roll-up (the entitlement_pruning_before_aggregation_no_leakage test anchors this).
- Observability is layered at exactly the right seam: the hot core (celnet-engine) carries no tracing/metrics/hdrhistogram dependency by construction (celnet-observability owns all of it, OBSERVABILITY.md §7), and the zero-hot-path-cost claim is a tested gate (tests/zero_alloc.rs + telemetry-on/off divan baseline), not an assertion.
- Telemetry-vs-audit separation is principled: distinct rings, drop-on-full for telemetry vs lossless/back-pressured/fsync for the booking-relevant audit trail (OBSERVABILITY.md §6) — a correct cross-cutting decision that prevents observability from corrupting trade lifecycle integrity.
- The deny-by-default Enforce posture is tested against the PRODUCTION posture (absent_principal_denied_on_every_entitlement_gated_service, enforce_denies_absent_principal_unauthenticated), with allow AND deny both audited (audit_records_emitted_for_allow_and_deny) — the dev-posture-masks-prod-defects lesson is encoded for the handlers that ARE gated.

**Risks:**
- ACCESS GATE IS NOT A CROSS-CUT — it is hand-copied per handler. `resolve_caller(...) + authorize_caller(...)` is duplicated verbatim in 4 risk/mod.rs methods (lines 699,725,751,777) and 6 fix_admin.rs methods (135-310). There is NO tonic interceptor or tower::Layer (grep for Interceptor/ServiceBuilder/tonic layer = empty). A new RPC handler is access-gated only if the author remembers to paste the pair — a textbook scattered cross-cut and a security-by-omission trap.
- PRICE/SUBSCRIBE/EXECUTE HOT PATH IS UNGATED. stream.rs (Session.handle_subscribe / handle_execute) and pricefanout.rs call authorize/resolve_caller ZERO times. The deny-by-default guarantee covers RiskService + FixAdmin only; the highest-value capability (executing a click-to-trade token, subscribing to a stream) has no access gate — the entitlement pruning filter prunes risk FACTS, it does not authorize a subscribe/execute action.
- THE WS-JSON MIRROR HAS NO ACCESS GATING AT ALL. ws/mod.rs + ws/codec.rs reference authorize/resolve_caller zero times. The contract claims gRPC and WS are 'one contract, two encodings', but the deny-by-default access gate is a gRPC-handler property that does not span to the WS transport — an entitlement enforcement asymmetry between the two encodings of the supposedly-single contract.
- ERROR TAXONOMY IS DOCUMENTED-NOT-WIRED. OBSERVABILITY.md §6 states the #[repr(u16)] ErrorClass 'maps deterministically to gRPC status at the edge', but celnet-server references ErrorClass ZERO times. The edge uses tonic::Status independently; WS status_error merely stringifies status.code() via format!("{:?}"). Telemetry's error vocabulary and the client-facing error vocabulary are two disjoint enums with no bridge — a client error code can drift from its logged ErrorClass with nothing to catch it.
- ADR-0009 (celnet-wire-edge / EdgeFrame fixed-offset codec) is still PROPOSED — no crate exists (crates/ has no wire/edge dir), no proto-consistency test exists. The streamed price edge therefore still uses prost/JSON, so the 'two encodings of one contract kept in lockstep by a build-time consistency gate' that the ADR relies on is not yet a guard; if/when it lands without that gate, the edge frame and proto Update can silently drift.
- The grant-all-everywhere client default (every client asserts explicit grant_all) is the correct migration anchor, but it means in-repo NO client ever exercises a restrictive principal end-to-end against a gated handler — the deny path is unit-tested server-side but not driven through the SDK/GUI/Excel clients, so a client-side principal-encoding regression would pass all client e2e suites (the deferred-e2e-defect-reservoir failure mode).

**Optimal:** Target shape: each cross-cut enforced ONCE, at the lowest layer that spans every transport, with a gate that fails closed.

1) ACCESS GATE → a single tonic interceptor + an equivalent WS-frame guard, both reading ONE per-RPC RequiredAuthority table. Replace the 10 hand-copied resolve_caller+authorize_caller pairs with a tower::Layer / tonic Interceptor that resolves the caller once and authorizes against a static `&[(rpc_path, RequiredAuthority)]` registry; add the same guard at the WS dispatch in ws/mod.rs so the 'two encodings of one contract' actually share enforcement. Make 'unlisted RPC' default to deny (fail-closed) so a new handler is denied until explicitly registered — invert the current paste-or-forget default.

2) GATE THE STREAM/EXECUTE PATH. handle_subscribe and especially handle_execute (token redemption) must run an authorize check + an entitlement scope check on the subscribed instrument BEFORE booking. The pruning filter is necessary-not-sufficient; execute is an action, not a read, and needs its own capability gate.

3) UNIFY THE ERROR TAXONOMY. Make celnet-observability::ErrorClass the single source and implement `From<ErrorClass> for tonic::Status` (and have the WS status_error derive its code from that same mapping), so the logged class and the client-facing code are provably the same enum — wire it where handlers build their Status, and add a round-trip test (ErrorClass → Status → WS-JSON code) so OBSERVABILITY.md §6 becomes a gate instead of prose.

4) DRIVE A RESTRICTIVE PRINCIPAL THROUGH AT LEAST ONE CLIENT E2E (SDK or GUI) against a gated handler under Enforce, asserting the deny path renders correctly — close the client-side principal-encoding blind spot.

5) When ADR-0009 is accepted, land the proto-consistency build gate (EdgeFrame field-set == streamed projection of celnet-proto::Update) in the SAME change as the codec, never after — the ADR's lockstep guarantee is only real if the gate exists from day one. Keep the entitlement principal mirroring as the template for how every cross-cutting wire concern should look — that is the dimension's exemplar.

- STALE DOC vs CODE on the fleet transport: INTERFACES.md §dependency-direction line 67-68 and ARCHITECTURE.md §125-132 both state `celnet-risk-fleet` is 'fan-out == single-node (transport designed-only)' / 'transport designed-only', but `celnet-server/src/services/risk/federate.rs` + `tests/risk_federation.rs` implement and gate REAL cross-process gRPC federation with failover. The authoritative interface registry understates a built capability — a coordination hazard for any session trusting the doc.
- TWO ENCODINGS OF ONE CONTRACT WITH NO GENERATOR GATE: the WS mirror in `celnet-server/src/ws/codec.rs` is hand-maintained — `product_from_json` (cyclomatic 24), `handle_unary` (30), and 253 `*_from_json` functions kept in lockstep with the proto by 253 hand-written per-product round-trip TESTS, not by a generated-from-proto consistency check. ADR-0009 §2.2 prescribes 'one generator, two projections / drift fails CI' for EdgeFrame, but that build-time generation discipline is NOT applied to the existing JSON WS codec. Every new proto arm requires a manual codec edit + a manual test; drift is caught only if someone remembers to add the test.
- ADR-0009 (`celnet-wire-edge`/`EdgeFrame`) is PROPOSED and unbuilt — the graph has no wire-edge symbol. The §1.2 hot-edge budget (≥1M updates/s/core; p99 ≤10µs) is met on COMPUTE but the streamed price line still pays prost/JSON per-tick serialize cost — the very jitter source ADR-0009 §1 identifies as 'the next-largest controllable contributor to tail latency on that path' remains in place.
- CELER INGRESS IS UNDECIDED: CELER-INTEGRATION.md §0 flags the JVM-distributor adapter-vs-socket-protocol choice as a blocking decision that 'determines the entire ingress/egress transport' and it is still 'pending.' `celnet-integration` builds a clean normalize/blend/egress pipeline, but the actual seam to the live Celer bus has no committed transport — the single largest open integration-scale boundary.
- Cross-host edge SLOs are deploy-gated and unmeasurable in-repo (ADR-0009 Phase 3; SCALE-OUT §11/§12): the many-counterparty fan-out tail SLO ('X µs to N receivers') and kernel-path levers (`SO_REUSEPORT`/eBPF built; io_uring/XDP/DPDK deferred) cannot be validated here, so the absolute horizontal-scale claim rests on benchmarks that only exist on deployed infrastructure.
- Risk facts are vanilla-only: `services::risk::store` records only vanilla fills as canonical leaves (an exotic 'has no canonical-vanilla leaf — not recorded, never faked', INTERFACES.md). The risk-cube/fleet federation therefore does not yet cover the exotic/cross-asset book it prices — a real coverage gap between the pricing surface and the risk surface.

**Optimal:** Target: ONE contract, ONE generator, N transports — every encoding a checked projection of the proto source of truth, and a fleet whose transport is real, documented, and exotic-complete.

1. CLOSE THE WS DRIFT SEAM (highest leverage, in-repo). Apply ADR-0009 §2.2's 'one generator, two projections' discipline to the EXISTING JSON WS codec, not just the future EdgeFrame: generate `ws/codec.rs` (or a field-set consistency assertion) FROM `celnet-proto` so a new proto arm cannot compile without its WS projection, retiring the 253 hand-written round-trip tests as the only drift guard. This removes the single most fragile integration seam.

2. RECONCILE DOCS TO BUILT REALITY. Update INTERFACES.md §dependency-direction and ARCHITECTURE.md §layout to state that fleet federation transport IS built (`celnet-server/src/services/risk/federate.rs`, real gRPC + failover, gated by `risk_federation.rs`); reserve 'designed-only' strictly for the pure `celnet-risk-fleet` algebra crate. Author lodestar knowledge claims (currently zero on `fan_out`/`firm_aggregate`/`producer_loop`) anchoring the disjoint-cover and `received+skipped==produced` invariants so the why-layer matches the code.

3. RESOLVE THE CELER INGRESS DECISION (the real scale-out boundary). Promote CELER-INTEGRATION.md §0 to an ADR: pick JVM-adapter-sidecar vs `DistributorProducerChannelHandler` socket protocol, define the handshake/back-pressure contract, and wire `celnet-integration::egress`/`subscriber` to it behind a transport trait so the in-repo pipeline (normalize/blend/divergence) terminates in a committed seam rather than an open question.

4. BUILD ADR-0009 EdgeFrame as accepted, behind transport-negotiation-at-handshake (its Phase 0-2 are fully in-repo gatable: to_bits identity, zero-alloc, cross-arch golden, decode fuzz). This removes the per-tick prost/JSON parse from the HFT-facing line while staying inside #9 (transport choice, not version choice).

5. EXTEND RISK-FACT COVERAGE TO EXOTICS/CROSS-ASSET. The risk fleet's scale-out boundary is sound, but its INPUT is vanilla-only. Define a canonical risk-leaf projection for exotic/cross-asset fills (or a sensitivities-based fact) so the federated cube covers the book the platform actually prices — otherwise horizontal risk scale-out is over a strict subset.

Scale-out boundary verdict: the partition (HRW by pair/tenant) and the additive/non-additive merge algebra are the correct shard boundary and are bit-identically proven; the fleet scales horizontally per the budget AS DESIGNED. The binding constraints are not the algebra but (a) the unbuilt zero-copy hot-edge codec, (b) the undecided Celer ingress transport, and (c) the hand-maintained WS projection — fix those three and the integration is genuinely horizontally scalable end-to-end.
