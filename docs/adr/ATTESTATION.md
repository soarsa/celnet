# ADR & decision-claim attestation register

**Purpose.** Celnet's governance knowledge — ADR claims (`kind:adr`) and design/architecture
decision claims (`kind:decision`) in the lodestar verified-knowledge layer — cannot currently be
promoted to `active` by the Stage-2 cross-model review gate. Two upstream gaps block it:

- **No Stage-2 verdict transport** — the engine bundles no reviewer model and exposes no path to
  record a cross-family `affirm/refute` verdict for `decision`/`adr` kinds, so they never leave
  `draft`. Filed: **soarsa/lodestar#52**.
- **Acceptance targets / design-target sentinels are unmaterialized** — the 10 committed
  `docs/acceptance/*.acceptance.json` targets produce **zero** `Deliverable` graph nodes, so
  `manage_adr` cannot create `Decision -GOVERNS-> Deliverable` edges (the link defers) and
  `spec:satisfies` roll-ups cannot surface children. Filed: **soarsa/lodestar#52 / #19**.

**What this file is.** A coordinator **attestation of record**: the decisions below are accepted
and authoritative for the platform pending the upstream fix. It is **NOT** a Stage-2 verdict and
does not forge one — the `never-self` rule is honored (no `verdict=` was hand-written onto any
claim; the claims remain honestly `draft` in the graph). When #52/#19 land, each claim gets a
real cross-family review and each acceptance target is re-indexed so `manage_adr` can attach the
`GOVERNS` edges; this register is then retired.

**Attested:** 2026-07-01 — coordinator (Claude Opus 4.8 knowledge session). Claims keyed by
machine-local content-addressed id **and** a content descriptor (the id can churn across index
generations; the descriptor is the stable identity).
