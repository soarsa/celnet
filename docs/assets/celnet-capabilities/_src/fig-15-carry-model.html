Generalized-BSM core
Carry answers how the underlying drifts and discounts by producing only a forward and a discount factor. Every asset class differs solely in how the carry rate b is assembled from its named factors — the maths below is identical for all of them.

Why it holds — the binding no-workaround rule
The no-workaround test
A payoff engine that branches on which carry it was handed — FX rates here, cost-of-carry there — is a failure of the abstraction, not a shortcut to accept; it is a review blocker. Every payoff asks the inputs only for a forward and a discount factor, and nothing else about carry.
Multi-curve ready
A flat-rate carry is the degenerate single-point curve. OIS/CSA discounting and basis slot behind the very same forward / discount interface — proof the seam is in the right place — with zero payoff-engine changes.
No silent mis-pricing
A product × underlying validity matrix yields a typed invalid-argument error, never a fallback. An FX payoff handed a non-FX carry errors rather than guessing — clients default to FX, so every existing ticket is unchanged.
Zero-alloc reconciled with general: the hot-core Greek block keeps a fixed, fixed-size shape carrying a compact rate-sensitivity descriptor; the FRTB factor decomposition into GIRR / equity / commodity / CSR buckets happens off the hot path in the already factor-generic risk layer, where the domestic and foreign rate sensitivities split exactly out of the discount and carry sensitivities — recovered to the last bit by the AAD adjoint.
