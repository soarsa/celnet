How LPs Are Enabled & Integrated Today

Across the codebase, liquidity providers participate in three distinct institutional workflows. While each individual pathway contains sophisticated quantitative logic, the three pathways are currently disconnected from each other:

1. Multi-Dealer RFQ Quoting

Workflows: FX Options & Rates RFQ
Crates: celnet-rfq, celnet-server::quote

When a client requests a quote, the request fans across an LP panel. The server ranks competing dealer lines (best bid/offer) with last-look deadlines.

Current Enablement: Controlled by CELNET_DEMO_LPS env variable. Synthesizes SYNTH-LP-1..N mathematically in-memory. Does not query connected FIX acceptors.

2. Streaming Book Aggregation

Workflows: Cash Bonds & Treasuries
Crates: celnet-aggregation, fix_admin

Multiple LPs stream top-of-book quotes. ConsolidatedBook computes robust median consensus with MAD outlier gating and staleness decay.

Current Enablement: Defined in fix_connections.json and joined to aggregated_books.json member arrays. Monitored via LiquidityWorkspace.tsx.

3. Outbound Auto-Hedging

Workflows: Risk Shedding & Exit
Crates: celnet-hedge-routing, auto_hedge

When warehouse bands breach (delta/DV01), the auto-hedge engine routes hedge orders to an external LP panel or CME futures venue.

Current Enablement: Configured in hedge_policy_graph.json under HedgeLpPanel. Routes via StreetOrderIntent to LpHedgeSource.
Gap Analysis

The 4 Core Architectural Fragmentation Gaps

Gap 1: Triplicate Entity Models for the Same Institutional Counterparty

Domain Fragmentation

If Barclays provides liquidity to Celnet across FX Options RFQ, Treasury Bond streaming, and Auto-Hedge execution, the platform currently represents Barclays as three completely disjoint entities:

  • In RFQ: A generated synthetic string "SYNTH-LP-1" in crates/celnet-server/src/services/quote.rs.
  • In Aggregation: A FixConnectionDef with ID "barclays-bond-feed" in fix_connections.json.
  • In Auto-Hedging: A member string inside HedgeLpPanel.members in hedge_policy_graph.json.

Gap 2: RFQ Quoting Engine Disconnected from Active Connections

Hardcoded In-Memory Logic

While celnet-rfq has a real FixLpAdapter capable of dialing LPs over FIX, celnet-server::services::quote does not query the active FIX connection registry. Instead, it reads CELNET_DEMO_LPS and mathematically shifts its own internal mid by (5% × k) to create fake quotes. A real bank connecting over FIX cannot join the RFQ panel dynamically without code changes!

Gap 3: Fragmented Operator Controls & No Single Kill-Switch

Operational Risk

If an LP exhibits erratic quoting, credit distress, or extreme last-look rejection toxicity, an operator currently has no single command to disable that LP. They must:

  • Disable its connection in FixAdminService (stops streaming feed).
  • Remove it from book member arrays in AggregatedBookService.
  • Update the hedge routing graph in HedgePolicyService to prevent order fills.
  • Restart the edge with modified CELNET_DEMO_LPS (for RFQ).

Gap 4: Disjoint Trader GUI Across 5 Separate Workspaces

User Experience Friction

In the GUI, an institutional head of trading or operations manager must flip between 5 disparate screens to inspect a single LP:

  • FixAdminWorkspace.tsx (Desk 06): Connection IP, port, session heartbeat.
  • LiquidityWorkspace.tsx (Desk 01): Feed health, fresh vs stale quotes, top-of-book %.
  • AggregatedBookWorkspace.tsx (Desk 03): Depth ladder and member bid/offer contributions.
  • StreetLiquidityWorkspace.tsx (Desk 06): Deals won, won notional, misses, last-look toxicity.
  • HedgingWorkspace.tsx (Desk 05): Auto-hedge venue routing.
Target Architecture

The Unified Liquidity Architecture (ULA)

To achieve a clean, optimal, unified architecture, Celnet must unify LPs into a First-Class Domain Entity managed by a centralized server registry and surfaced through an intuitive, consolidated Liquidity Center in the GUI.

1. Unified LP Domain Contract (in celnet.proto)

A single canonical message defining an LP and its multi-capability roles:

message LiquidityProvider { string lp_id = 1; // e.g. "BARCLAYS" string display_name = 2; // e.g. "Barclays Capital" string institution_code = 3; // e.g. "BARC" // Master Operator Kill-Switch bool enabled = 4; // False ⇒ instantly halts all flows to/from this LP // Supported Operational Capabilities LpRfqCapability rfq = 5; // Can receive RFQs (FX Options, Rates OIS/Bonds) LpStreamingCapability streaming = 6; // Streams top-of-book into Aggregated Books LpHedgeCapability hedging = 7; // Eligible destination for auto-hedging shed clips // Connectivity Endpoints repeated FixConnectionSpec fix_sessions = 8; // Associated FIX sessions repeated string desk_ids = 9; // Desks entitled to trade with this LP // Unified Real-Time Telemetry LpUnifiedTelemetry telemetry = 10; // Tick rate, stale quotes, deal win-rate, last-look latency }

2. Centralized LiquidityProviderRegistry in celnet-server

All three trading engines query the SAME in-memory, thread-safe registry:

+-----------------------------------+ | LiquidityProviderRegistry | | (Single Source of Truth in Core) | +-----------------------------------+ | | | +------------------------+ | +------------------------+ | | | v v v +------------------+ +-------------------+ +------------------+ | MultiDealerEngine| | AggregationHub | | StreetRouter | | (RFQ Quoting) | | (Streaming Books) | | (Auto-Hedging) | +------------------+ +-------------------+ +------------------+ | Fans RFQs ONLY to| | Ingests ONLY from | | Routes orders | | LPs with | | LPs with | | ONLY to LPs with | | .rfq.enabled | | .streaming.enabled| | .hedging.enabled | +------------------+ +-------------------+ +------------------+
Immediate Global Kill-Switch: When an operator calls SetLiquidityProviderEnabled(lp_id, enabled: false), the update publishes to the registry. Within microseconds, RFQs stop fanning to that LP, its streaming quotes are evicted from the composite books, and hedge orders steer to alternate venues.

Implementation Steps

Roadmap to Unify LP Enablement & Integration

Step 1: Unify Server Domain & Storage

Define message LiquidityProvider in celnet.proto. Implement LiquidityProviderRegistry in celnet-server backed by SQLite / WAL. Replace the CELNET_DEMO_LPS environment variable with dynamic queries against the registry.

Step 2: Connect RFQ Engine to FIX Acceptors

Wire QuoteEdge::request_multi_dealer_quote to fan out to all enabled LPs registered in the LiquidityProviderRegistry using FixLpAdapter or in-process SDK channels, eliminating the synthetic math loop in quote.rs.

Step 3: Unify Operator Kill-Switch RPCs

Expose SetLiquidityProviderEnabled(lp_id, enabled) on FixAdminService. Fan out changes to AggregationHub, MultiDealerEngine, and StreetRouter synchronously.

Step 4: Launch Unified Liquidity Center in GUI

Consolidate LiquidityWorkspace, StreetLiquidityWorkspace, and FixAdminWorkspace into the cohesive Liquidity Center component. Expose on Desk 03 (Distribution) and Desk 06 (Ops).
