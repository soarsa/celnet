Core Principle

The "Product vs External Actor" Clean Separation

The Fundamental Rule: The core platform (celnet-server, celnet-gui, excel/, numerical engine crates) must NEVER know whether an incoming request is part of a live trading day or a demonstration. It accepts real requests over standard wire protocols (gRPC, WebSocket, FIX), computes real mathematics, and returns real responses. All demonstration flow is generated by external client agents built with the official SDK.

✗ The Antipattern: In-Core Mocks

Hardcoding mock sources into the core products (e.g. mockSource.ts, pricing.ts, client-side fallback flags):

  • Pollutes production code with 11,000 lines of fake JavaScript state machines and approximated math.
  • Causes test suites to verify the mock's approximations rather than the true Rust engine.
  • Hides missing API contracts and wire serialization gaps.
  • Directly violates Guardrail #2: "No mocks, no placeholders, never fake depth."

✓ The SOTA Pattern: SDK-Driven External Agents

Building demonstration actors externally using the official celnet-client SDK:

  • Leaves core products 100% clean, production-ready, and verifiable.
  • Dogfoods the official SDK under continuous realistic trading load.
  • Executes genuine microsecond Rust pricing, AAD Greeks, and GPU tail risk for every demo interaction.
  • Enables rich, dynamic live demonstrations across all 6 desks (inbound RFQs, market depth, auto-hedges).

Demonstration Fleet

The 5 SDK-Driven Demonstration Agents

1. Market Maker Agent (celnet-demo-fleet::market_maker)
SDK: celnet-client • gRPC / WS

Purpose: Powers the dynamic market life of Desk 01 (Market Studio). Instead of static fixtures or client-side timer intervals, this agent runs as an external market maker:

  • Periodically issues SurfaceService.MarkSurface calls with live broker quote adjustments, causing the 3D volatility surface to breathe and morph dynamically.
  • Ticks SOFR and EURIBOR interest rate curve pillars via SurfaceService.MarkCurve, keeping par rates and discount factors alive.
  • Streams two-way liquidity feeds into celnet-aggregation to populate the Aggregated Order Book depth ladders.
2. Multi-Dealer LP Fleet (celnet-demo-fleet::dealers)
SDK: celnet-client / FIX 4.4

Purpose: Powers the competitive quoting panel on Desk 03 (Distribution Studio). Replaces in-core synthetic LPs with real external dealer clients:

  • Spawns 3 independent dealer processes (e.g. BARCLAYS-SIM, CITI-SIM, BNP-SIM) authenticated with real API tokens.
  • Listens for broadcast RFQs over gRPC or FIX.
  • Computes competitive bids and offers using distinct skew and inventory models, returning genuine ranked quotes over the wire.
  • Accepts trade allocations when the trader clicks a dealer line, confirming execution with real timestamped tokens.
3. Institutional Client Flow Bot (celnet-demo-fleet::client_flow)
SDK: celnet-client • gRPC

Purpose: Creates the living trading floor experience on Desk 03 (Distribution) and Desk 04 (Blotters):

  • Simulates tier-1 hedge funds, corporate treasurers, and asset managers submitting RFQs.
  • Generates realistic cross-asset flow: FX Vanillas (EUR/USD, USD/JPY), 23 Exotics (Barriers, Cliquet, TARF), SOFR OIS Swaps, and US Treasury Cash Bonds.
  • When a trader prices an RFQ on the desk, the bot evaluates the price against a calibrated hit-ratio model and accepts or rejects in real time.
  • Every accepted trade lands in the real server ledger (celnet-replog) and updates the blotters instantly.
4. CME Venue & Auto-Hedge Gateway (celnet-demo-fleet::cme_venue)
SDK: celnet-fix • FIX 4.4 / 5.0 SP2

Purpose: Demonstrates real execution on Desk 05 (Hedge Cockpit) without requiring a live WAN link to CME Group:

  • Binds as a standard FIX acceptor on 127.0.0.1:9800 speaking FIX 4.4 / 5.0 SP2.
  • When Celnet's Auto-Hedging engine detects warehouse band breaches (delta/DV01), it fires a NewOrderSingle(D) to this venue.
  • The gateway matches against the simulated Treasury futures order book and sends an ExecutionReport(8) back to Celnet.
  • Proves the entire automated hedging loop from risk breach → order routing → execution → blotter update end-to-end.
5. Four-Eyes Risk Transfer Approver (celnet-demo-fleet::four_eyes)
SDK: celnet-client • WebSocket Notification Push

Purpose: Demonstrates the institutional maker-checker governance workflow on Desk 04 (Risk Transfer):

  • Authenticates as a second user (e.g. head.of.desk@celnet.com) and opens a subscribe_notifications channel.
  • When a trader submits an inter-desk risk transfer from the GUI, a notification pops into the supervisor's inbox.
  • The agent inspects the transferred delta/DV01, validates that the four-eyes rule is met (initiator ≠ approver), and executes accept_risk_transfer.
  • Demonstrates complete compliance auditability without any client-side synthetic lot mocks.
