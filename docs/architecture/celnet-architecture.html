Architecture · Current → Target
One cross-asset contract, now landed — from disconnected islands to a unified platform

Celnet's central-core unification has landed on origin/main: options and fixed income now speak one Priceable / MarketResolver / RiskMeasure contract, dispatch through one PricingEngine, and aggregate in one risk cube — with FI first-class in the GUI, Excel, SDK and CLI. This map shows the CURRENT (landed) state honestly against the TARGET that remains: a single Price(Instrument) RPC, XVA/scenario on every surface, credit & inflation leaves, rates streaming/RFQ, and full elastic scale-out.

LIVE — landed on origin/main, gated (t2 19/19) PARTIAL — wired but incomplete / not yet on the live path TARGET — planned or in-flight (design/proto window)
↻

The whole-platform audit's dominant finding: Celnet had built genuinely state-of-the-art capabilities to a high standard and left many of them unwired from the live path — SOTA capability as disconnected islands. The architectural win was therefore integration and de-duplication, not new capability. The central pricing kernel (unified gBSM, ADR-0012) and the wire shape were already right; the program connected the islands, unified the substrate, and deleted the duplication — and the pricing/risk unification is now done and byte-identical.

01The one contract — landed

Every asset class implements the same three seams in celnet-core/src/contract.rs. Leaves price against a request-tier ResolvedMarket (the shared DiscountCurve seam), report a tagged RiskMeasure, and are dispatched by one stateless PricingEngine. Re-seating was proven byte-identical (to_bits) at every step — the hot core is untouched (ADR-0016 embargo). Ref: ADR-0020, Central-Core Phases A1/A2/A2b/B/C.

Hard invariant preserved through the whole unification. The term-structure Curve lives strictly in the request/batch tier; the streaming hot path keeps flat f64 rates. FX pricing stays byte-identical (to_bits) across the generalization — the flat-carry CPU path remains the sole byte-identity oracle. Numerical code is validated to ≤1e-12 against independent oracles (QuantLib / BCBS published / hand-derived), never a self-referential regen.
