Section 01

Deep Research & Critique: The 4 Pillars

Comprehensive Analysis
[01] Architecture & Contract Integrity

Contract Fragmentation & Split Engines

While celnet-core provides a clean abstract Priceable trait, the service edge drifted into fractured silos:

  • Wire RPC Split: PricingService exposes Price (FX), PriceRates (IR), and PriceXva (XVA). Clients must branch on asset type instead of using a unified polymorphic verb.
  • Duplicate Engine Registries: pricer/engines.rs (FX options) and rates_pricing/engines.rs (Fixed Income) duplicate dispatch, error wrapping, and model lookup logic.
  • Triplicated Rule Machinery: celnet-risk-routing, celnet-acceptance, and celnet-hedge-routing each maintain separate ASTs, serialization formats, and UI builders for the same underlying Match(Predicate) → Action graph.
[02] Performance & Low-Latency Core

Hot-Core vs Service-Edge Allocation Gap

The pricing kernel in celnet-engine achieves microsecond updates via ArcSwap, core pinning, and lock-free rings. However, the outer tiers introduce severe overhead:

  • Heavy JSON Allocations: ws/codec.rs dynamically manipulates serde_json::Value trees on every incoming/outgoing frame, triggering extensive heap allocations.
  • Repricing Inefficiencies: In surface.rs:867, Scenario re-evaluates 2D grids by repeatedly cloning the instrument and calling price_instrument sequentially on a single thread.
  • String Formats on the Hot Path: Underlier resolution and audit logging frequently format strings (e.g. format!("{asset}:{symbol}")) instead of zero-copy fixed-byte slices.
[03] Distribution & Streaming Scaling

Siloed Fanout & Dormant Consensus

Distribution mechanisms are partitioned unevenly across products:

  • Hardcoded FX Assumption: In services/stream.rs:2140, market-series observation hard-aborts for non-FX with Status::unimplemented.
  • Disconnected Tiering: celnet-tiering applies margin skews only to the Fixed Income aggregated book; FX options streaming and RFQ bypass the tiering engine.
  • Dormant Raft Consensus: celnet-replog contains 6,147 LOC of robust Raft replication, but the server boots in standalone in-memory mode by default.
[04] Acceleration & Hardware Offload

Unwired GPU Compute & Missing SIMD

Substantial acceleration infrastructure was built but never integrated into live endpoints:

  • Isolated GPU Shaders: celnet-gpu has complete WGSL compute shaders (batch.wgsl, greeks.wgsl, scenario.wgsl), but they are invoked solely by benchmarks and tests.
  • Dormant Risk Accelerator: celnet-risk-accel wires BatchPricer into ScenarioReprice, but was left unregistered in root workspace dependencies.
  • Absence of Vectorized SIMD: CPU fallbacks evaluate scalar f64 paths sequentially rather than utilizing AVX2/NEON portable SIMD intrinsics.

Target Unified Backend & Single Contract

Single Contract Architecture

The Unified Contract Specification (celnet.proto v-Next)

All disparate endpoints collapse into a single polymorphic wire service: 

// Unified Pricing Service — Calculates PV, 13 Greeks, Key-Rate DV01 Ladder, CS01, and XVA
service PricingService {
  rpc Price(PriceRequest) returns (PriceResponse);
  rpc PriceBatch(PriceBatchRequest) returns (PriceBatchResponse);
}

// Unified Streaming Service — Bidirectional multiplexed stream for all assets
service StreamService {
  rpc StreamSession(stream StreamRequest) returns (stream StreamMessage);
}

// Unified Quote Service — Two-way contribution, Inbound RFQ, and Multi-Dealer Auto-Quoter
service QuoteService {
  rpc RequestQuote(QuoteRequest) returns (Quote);
  rpc RequestMultiDealerQuote(QuoteRequest) returns (MultiDealerQuote);
  rpc AcceptQuote(QuoteAccept) returns (Execution);
}

// Unified Risk & Ledger Service — Cross-Asset Joint Tail Risk & Replicated Book
service RiskService {
  rpc ListPositions(ListPositionsRequest) returns (ListPositionsResponse);
  rpc AggregateRisk(AggregateRiskRequest) returns (AggregateRiskResponse);
  rpc CombinedTailRisk(CombinedTailRiskRequest) returns (CombinedTailRiskResponse);
}
