1. The Latency Chasm & The In-Core Paradox
EMPIRICAL REALITY

Celnet's numerical core (celnet-vanilla) is one of the fastest options pricing engines in existence, computing the full 14-member Greek strip in 42 nanoseconds. Within the same address space, celnet-fanout passes native Copy structs across thread boundaries in 4.2 nanoseconds.

Yet, when an algorithmic client or desk trader connects over loopback gRPC/TCP, round-trip latency surges to 588,000 nanoseconds (588 µs). Over 99.9% of user-observed latency is consumed by serialization, memory copying, socket buffers, and the OS networking stack.

The In-Core Paradox: Adopting SBE or Aeron inside the pinned pricing core would actually degrade performance by 44% (6.11 ns SBE vs. 4.23 ns native copy). However, at the IPC and network edge, replacing gRPC/TCP with SBE flyweights over shared memory and Aeron UDP multicast compresses latency from 588 µs down to <500 ns—a >1,000x speedup!
2. Deep Technical Critique of Current Mechanisms
CODEBASE REVIEWS

A. In-Process Fan-Out: crates/celnet-fanout

The single-producer multi-consumer ring buffer implements an atomic seqlock with a writer-in-progress stamp. Lines 326–345 in ring.rs correctly include an explicit fence(Acquire) for ARM64 architectures, preventing speculative read hazards on Apple Silicon and AWS Graviton.

  • SOTA Parity: Zero-allocation hot path, deterministic counted-skip conflation (received + skipped == produced).
  • Limitation 1 (Single Process): Backed by Arc<Inner<T>>. Lacks cross-process shared-memory capabilities; an edge thread crash compromises the core address space.
  • Limitation 2 (No Batch Drain): Reads one slot per invocation; Disruptor-style batch consumption would amortize head loads.

B. Wire Serialization: crates/celnet-proto (Protobuf v3 via prost)

Protobuf v3 serves as the single unversioned wire schema for all gRPC and WebSocket streams. While ideal for control-plane tooling, it introduces severe bottlenecks on high-frequency market data:

  • Varint Bit-Shifting Tax: LEB128 encoding branches heavily on every field tag and integer, causing CPU branch mispredictions.
  • Heap Allocation on Decode: String fields and nested structures force dynamic allocations on the receiving side.
  • Empirical Latency: 78 ns encode + 192 ns decode = 270 ns per quote (44.2x slower than SBE).

C. Durable Log & Replication: celnet-journal & celnet-replog

celnet-replog implements a complete Raft consensus engine with log compaction, snapshot distribution, and bit-identical replay. However, the journal framing exhibits one critical audit vulnerability:

  • Marker-less Framing Risk: Framing uses payload_len:u32 || seq:u64 || payload || crc32:u32. A single interior flipped bit corrupts length parsing, forcing truncation of all subsequent acknowledged transactions.
  • Allocating Decoder: LogEntry::decode allocates dynamic Vec<u8>s during replay instead of yielding zero-copy slices.

Analyzes cache line prefetcher behavior across SBE, FlatBuffers, Cap'n Proto, and Protobuf. Confirms that SBE's compile-time fixed offsets avoid pointer indirection stalls, yielding 10x–50x throughput advantages over Protobuf while completely eliminating heap fragmentation.
