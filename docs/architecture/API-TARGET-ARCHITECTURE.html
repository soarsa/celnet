Executive Summary & Motivation

Celnet has achieved state-of-the-art numerical performance across 55 modular Rust crates, sub-microsecond pricing kernels, and hardware-accelerated risk engines. However, rapid multi-asset expansion produced functional silos at the network edge: fixed-income pricing and risk were grafted onto parallel RPC verbs, and administrative capabilities congregated into a massive God-service.

💡

The Core Architectural Objective

Transition Celnet from a collection of asset-specific endpoints into a Single Cohesive Multi-Asset Platform. A trader, algorithmic bot, Excel spreadsheet, or institutional FIX client should interact with identical, intuitive primitives whether pricing a EUR/USD 25-delta risk reversal, quoting a 10Y SOFR OIS swap, analyzing a 30Y US Treasury bond yield curve, or simulating joint cross-asset tail risk.

Deep Structural Critique: The 6 Anti-Patterns

A forensic examination of the current API contract (celnet.proto) reveals accumulated technical debt resulting from organic, multi-wave additions. Below is the honest critique of the six primary architectural deficiencies.

1. Severe Asset-Class Fragmentation on Core Verbs
High Blast Radius

Rather than treating products polymorphically, the wire contract fractures core calculation and trading operations across parallel RPC methods keyed by asset class:

Current Bifurcated Contract Fragmented
  • Price(PriceRequest) — FX Options only
  • PriceRates(RatesPriceRequest) — Linear FI only
  • PriceXva(PriceXvaRequest) — CVA/DVA/FVA only
  • RequestQuote vs RequestRatesQuote
  • AggregateRisk vs AggregateRatesRisk
  • ListPositions vs ListRatesPositions
  • BookRatesPosition (Options booked via Execution)
Target Unified Contract Polymorphic
  • Calculate(ValuationRequest) — Universal for all assets
  • RequestQuote(QuoteRequest) — One RFQ verb for all
  • AggregateRisk(RiskRequest) — Universal roll-up cube
  • ListPositions(PositionFilter) — Single position store
  • BookPosition(BookRequest) — Standardized booking
  • Adding Credit/Inflation/Crypto requires zero RPC additions

Consequence: Every client (GUI, Excel, SDK, CLI) is forced to maintain manual switch statements before calling the server. A trader combining a bond future hedge with a currency option must invoke two distinct services, losing atomicity.

2. The "God-Service" Anti-Pattern in AuthService
Domain Coupling

service AuthService currently houses 38 RPC methods. Because it was the first stateful service created, it became the dumping ground for seven completely unrelated architectural domains:

RPC Group in AuthService Actual Domain Why It Does Not Belong in Auth
ListDesks, CreateDesk, UpdateDesk... Organization / Enterprise Hierarchy Trading desk layout is business structure, not session verification.
ListAggregatedBooks, SetPricingControl Liquidity / Market Ingest Managing venue quote consolidation has zero connection to credential verification.
ListPricingGroups, UpdatePricingGroupPipeline Client Tiering & Distribution Outbound spread markups and inventory skew pipelines are pricing features.
GetRiskRoutingGraph, UpdateRiskRoutingGraph Order Execution & Risk Policy Routing fills into hierarchical risk books is a mission-critical trading policy.
GetHedgePolicyGraph, ListHedgeThresholds Algorithmic Auto-Hedging Decision trees for internalizing vs warehouse vs market order execution.
InitiateRiskTransfer, AcceptRiskTransfer... Risk Governance & Transfers Four-eyes desk-to-desk risk transfer workflow.
3. Transport & Streaming Disjointedness
Resource Inefficiency

While StreamService.StreamSession is a modern bidirectional multiplexed channel for streaming prices, push notifications were implemented as standalone streams:

  • NotificationService.StreamNotifications (Stream 1)
  • NotificationService.StreamRiskTransferInbox (Stream 2)
  • StreamService.StreamSession (Stream 3)

Consequence: A single GUI or Excel instance opens 3+ persistent HTTP/2 or WebSocket connections. When network switches occur (e.g. laptop roaming or VPN blip), three independent reconnection and resync state machines execute, leading to out-of-order race conditions and wasted socket descriptors.

4. Asymmetric Taker/Maker Vocab
Cognitive Mismatch

Taker flows use QuoteService (RequestQuote → AcceptQuote → returns Execution). Maker desk flows use RfqDeskService (SubmitDeskRequest → RespondDeskRequest → returns Deal). Both represent the same trade, but speak conflicting terminologies.

5. SurfaceService Misnomer
Domain Blurring

SurfaceService was built for 2D FX volatility smile surfaces. When dual-curve fixed income landed, discount curves were appended: GetCurve, MarkCurve, CurveScenario. Curves are not surfaces; the service is actually a Market Data Engine.

6. SDK Ergonomics Divergence
Parity Gap

The Rust SDK uses fluent builders (client.pricing().vanilla(...)); the GUI transport manually serializes raw JSON strings; the Excel add-in fractures into =CELNET.PRICE vs =CELNET.RATES vs =CELNET.BOND. No unified client specification exists across languages.

03

Target Architecture Tenets

To guide the redesign and ensure long-term architectural stability, all target APIs must adhere strictly to the following six engineering laws.

Tenet I: Rule 9 Law (One Clean Unversioned Contract)

Zero schema_version fields. Zero semantic negotiation. Every field is strongly typed, every enum is explicit, and protobuf oneof structures default safely. Breaking changes are rejected; evolution is strictly additive.

Tenet II: Complete Transport Mirroring

Every single gRPC method and message must map 1:1 onto the WebSocket JSON transport. Field names, data structures, and error semantics are byte-identical across gRPC and WS.

Tenet III: Single-Seam Multiplexing

A client opens exactly ONE stateful connection to Celnet. All market data subscriptions, streaming two-way prices, live RFQs, order updates, risk triggers, and administrative alerts multiplex over that single channel.

Tenet IV: Pure vs Stateful Decoupling

Calculation services (ValuationService) are 100% stateless and side-effect free: caller provides the instrument and market, pricer returns math. Trading and booking services (TradeService, RiskService) are stateful, audited, and strictly journaled.

Deep Dive: ValuationService (The Universal Seam)

ValuationService completely retires Price, PriceRates, and PriceXva. It exposes a single, polymorphic, calculation-only endpoint capable of pricing any instrument across all asset classes.

proto/celnet/valuation/v1/valuation.proto protobuf 
syntax = "proto3";
package celnet.valuation.v1;

import "celnet/instrument/v1/instrument.proto";
import "celnet/market/v1/market.proto";

// The single calculation RPC for Celnet across ALL asset classes.
// Stateless: caller supplies instrument + market context explicitly.
service ValuationService {
  // Calculate fair value, full Greeks vector, and sensitivity ladders.
  rpc Calculate(ValuationRequest) returns (ValuationResponse);

  // High-throughput batched calculation for portfolio re-valuation.
  rpc BatchCalculate(BatchValuationRequest) returns (BatchValuationResponse);
}

message ValuationRequest {
  // Any supported instrument: Vanilla, Exotic, Bond, OIS, Swap, Future, CDS.
  celnet.instrument.v1.Instrument instrument = 1;

  // Complete market context: Spot, Discount Curve, Vol Surface, Hazard Curve.
  celnet.market.v1.MarketSnapshot market = 2;

  // Optional calculation parameters (pricing model, MC paths, FD grid size).
  optional ValuationConfig config = 3;

  // Caller correlation token echoed in response.
  optional uint64 correlation_id = 4;
}

message ValuationResponse {
  // Primary valuation measure: PV in base currency, clean price for bonds.
  double present_value = 1;

  // Secondary instrument-specific handle: e.g. YTM / Par Rate / Fair Strike.
  optional double par_rate_or_yield = 2;

  // 13-Greek vector for non-linear structures (Delta, Gamma, Vega, Theta...).
  optional OptionsGreeks options_greeks = 3;

  // Linear interest rate sensitivity (PV01, DV01, Key-Rate Tenor Ladder).
  optional RateSensitivities rate_sensitivities = 4;

  // Credit spread sensitivities (CS01, Jump-to-Default).
  optional CreditSensitivities credit_sensitivities = 5;

  // Monte Carlo standard error (absent for analytical / PDE closed-form).
  optional double price_std_error = 6;

  // Execution telemetry for transparency.
  uint32 compute_nanos = 7;
  string model_used = 8;
  optional uint64 correlation_id = 9;
}
✨

Why This Design is SOTA

When pricing an FX option, options_greeks is populated; when pricing a bond or OIS swap, rate_sensitivities is populated; when pricing a hybrid or cross-asset product, both populate seamlessly. The caller never changes their network stub.

Deep Dive: TradeService (Harmonized RFQ & Execution)

TradeService resolves the Taker/Maker terminology collision by creating a single, symmetric workflow. Whether trading on client requests or institutional inter-dealer liquidity, the domain model uses unified concepts: QuoteIntent → Quote → Execution.

proto/celnet/trade/v1/trade.proto protobuf 
service TradeService {
  // 1. Taker requests a two-way tradable quote (single or multi-dealer).
  rpc RequestQuote(QuoteRequest) returns (Quote);
  rpc RequestMultiDealerQuote(QuoteRequest) returns (MultiDealerQuote);

  // 2. Maker desk responds to an incoming client quote request.
  rpc RespondQuote(QuoteResponse) returns (Quote);

  // 3. Taker accepts a quote within the last-look window -> atomic execution.
  rpc ExecuteQuote(ExecuteQuoteRequest) returns (ExecutionReport);

  // 4. Either party declines / passes on the quote.
  rpc RejectQuote(RejectQuoteRequest) returns (TradeAck);

  // 5. Query active trades & blotter deals with entitlement filtering.
  rpc ListDeals(ListDealsRequest) returns (ListDealsResponse);
}

Deep Dive: RiskService (Universal Cube & Tail Engine)

RiskService manages the enterprise position store, runs real-time hierarchical risk roll-ups, monitors RAG limits, and calculates joint multi-asset tail risk (VaR / Expected Shortfall).

1. Universal Position Store

Positions are no longer segregated by asset class. Every position is an atomic fact carrying an Instrument, Quantity, BookId, TraderId, and AttributionRecord. A single ListPositions query returns the complete firm inventory.

2. Server-Side Aggregation Cube

Clients never sum risk numbers locally. The server prunes positions by principal entitlements, groups by organizational dimension (Desk, Book, Trader, Counterparty), converts to a common ReportingNumeraire, and re-derives non-additive measures (VaR, ES, FRTB curvature).

proto/celnet/risk/v1/risk.proto protobuf 
service RiskService {
  // 1. Query open positions across ALL asset classes.
  rpc ListPositions(ListPositionsRequest) returns (ListPositionsResponse);

  // 2. Hierarchical risk aggregation roll-up tree in reporting numeraire.
  rpc AggregateRisk(AggregateRiskRequest) returns (AggregateRiskResponse);

  // 3. Drill risk tree node down to child sub-nodes and contributing positions.
  rpc DrillRisk(DrillRiskRequest) returns (DrillRiskResponse);

  // 4. Read real-time limit utilization (RAG status, soft/hard breach alerts).
  rpc LimitStatus(LimitStatusRequest) returns (LimitStatusResponse);

  // 5. True joint multi-asset tail risk: aligned FX/Rate/Credit shock scenarios.
  rpc CombinedTailRisk(CombinedTailRiskRequest) returns (CombinedTailRiskResponse);
}

Zero-Downtime Migration & Cutover Strategy

To adhere to GUIDE.md guardrails and avoid breaking existing production tests, the transition will follow an orderly 4-stage migration:

Phase 1: Additive Schema Layer (Zero Breakage) Safe
  • Add ValuationService and TradeService to celnet.proto.
  • Wire internal dispatch in celnet-server directly to the existing pricing engines.
  • Legacy RPCs (Price, PriceRates) remain fully functional as thin pass-through adapters.
  • All existing tests (168 GUI, 122 Excel, 816 Rust) remain 100% green.
Phase 2: Client Transport Migration Client Update
  • Update Rust SDK (celnet-client) to prefer the unified ValuationService.
  • Update GUI transport (transport.ts) to stream via StreamService 2.0.
  • Consolidate Excel functions to =CELNET.PRICE.
  • Verify live GUI and Excel suites under CELNET_ACCESS_MODE=enforce.
Phase 3: Administrative Decomposition Domain Cleanup
  • Decompose AuthService into PolicyService, OrganizationService, and IdentityService.
  • Migrate administrative GUI panels (LP Panel, Hedging Workspace, Risk Transfer Inbox).
  • Update permission audit log and decision journal.
Phase 4: Deprecation Retirement (Rule 9 Cleanliness) Complete
  • Retire legacy adapter shims once all clients speak the unified contract.
  • Verify zero dead code and zero compiler warnings with cargo clippy -D warnings.
  • Celebrate a pristine, SOTA, unified multi-asset API!
