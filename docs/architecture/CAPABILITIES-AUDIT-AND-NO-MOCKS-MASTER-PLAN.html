Executive Summary

The "Real vs Mock" Architectural Reality

Core Audit Finding: The Rust backend is mathematically rigorous, industrial-strength, and 100% real. It contains 55 crates, 72 services, 39,508 graph nodes, and zero mocks. However, during early frontend prototyping, an 11,000-line shadow mock backend in TypeScript was constructed inside gui/src/data/ to support offline browser previews.

✓ What is 100% Real Today (Rust Engine & Edge)

  • Quantitative Pricing: Garman-Kohlhagen, Black-76, American BAW/Bjerksund-Stensland, and all 23 Exotic option families analytically solved in Rust.
  • Sensitivity Engine: 13 Greeks computed via reverse-mode Algorithmic Automatic Differentiation (AAD) in 42 ns.
  • Surface Calibration: 5 arbitrage-free smile parameterizations (eSSVI, SABR, SVI, Vanna-Volga) with Durrleman static arb elimination in 7.8 µs.
  • Fixed Income & Credit: Multi-curve SOFR/EURIBOR dual-bootstrap, cash bonds, CDS hazard rates, key-rate DV01 ladders.
  • GPU Tail Risk: Joint Close-to-Close (C2c) Options + Rates risk cube accelerated via WGPU/Metal at 416.2M paths/s.
  • Conflation & Wire: Single unversioned wire contract streaming at 23.8M pub/s through lock-free ring buffers.
  • Post-Trade & Policies: Real deal capture, four-eyes risk transfer approvals, pre-trade acceptance, and FIX 4.4/5.0 engine.

✗ Where Mocks Infiltrated (Frontend & Tests)

  • gui/src/data/mockSource.ts: 6,903 lines duplicating the entire backend in-memory in JavaScript (auth, books, streaming, RFQs).
  • gui/src/data/pricing.ts: 2,300 lines of JavaScript GK math with simplified approximations (flat vol on variance swaps, skipping window barriers).
  • gui/src/data/ratesPricing.ts & surface.ts: 1,840 lines of in-browser curve bootstrapping and quadratic log-delta smiles.
  • Surface Preview Bypass: SurfaceWorkspace.tsx calls local TypeScript calibrateLadder for edit previews instead of dialling celnet-server.
  • XVA Profile Boundary: PriceXvaResponse in celnet.proto omitted the bucketed exposure fan, causing XvaExposureFan.tsx to render an illustrative curve.
  • Risk Transfer Lot Synthesis: transferModel.ts splits portfolio risk into synthetic lots via a hash function instead of querying real server positions.
  • Vitest Test Suites: 203 GUI test files run with ?mock, asserting against the in-memory mock rather than the live Rust backend.

Code Forensics

Forensic Audit of Mock & Synthetic Seams

Seam 1: The 11,000-Line TypeScript Shadow Backend

Located in gui/src/data/mockSource.ts, pricing.ts, ratesPricing.ts, surface.ts, xvaPricing.ts

11,043 Lines • 500 KB Code

mockSource.ts contains a full, parallel implementation of auth, pricing, surface calibration, rates discounting, blotters, deals, and auto-hedging in JavaScript. In pricing.ts, certain exotics had to be approximated or omitted:

// gui/src/data/pricing.ts lines 367-373: // LOCAL_STOCH_VOL). The offline mock deliberately does NOT fabricate an LSV // number (CLAUDE.md: no mocks/placeholders/overclaim). The TicketWorkspace // surfaces this explicitly: throw new Error( "window-barrier pricing is server-side only (LOCAL_STOCH_VOL); the offline mock does not price it", );
The Problem: Whenever developers tested or reviewed features using ?mock, they were executing JavaScript math rather than the real, microsecond Rust engine. This violates Guardrail #2 ("No mocks, no placeholders").

Seam 2: XVA Wire Contract Truncation (Illustrative Fan Profile)

Located in crates/celnet-proto/proto/celnet.proto & gui/src/workspaces/XvaWorkspace.tsx

Wire Truncation

celnet-xva::ExposureProfile in Rust computes genuine EPE(t_k) and ENE(t_k) exposure profiles across Sobol QMC paths. However, XvaResult in celnet.proto only returned 4 scalars:

// crates/celnet-proto/proto/celnet.proto lines 8844-8854: message XvaResult { double cva = 1; double dva = 2; double fva = 3; double total_adjustment = 4; // MISSING: repeated ExposureBucket buckets = 5; }

Because the proto omitted the bucket array, XvaWorkspace.tsx was forced to document: "The simulated exposure PROFILE (EPE/ENE per bucket) is a server-internal... so the counterparty exposure fan is drawn from a clearly-labelled illustrative profile."

Seam 3: Volatility Surface Edit Preview Bypass

Located in gui/src/workspaces/SurfaceWorkspace.tsx (lines 536-544)

Local Calibration
// gui/src/workspaces/SurfaceWorkspace.tsx lines 536-542: const smiles = calibrateLadder( surface.pair, ladder, app.conventions, nowNanos(), app.surfaceModel, );

When a volatility trader edits ATM/RR/BF broker quotes, the live 3D mesh preview is calculated by calibrateLadder in TypeScript using a simplified quadratic log-delta smile, rather than sending a preview mark request to the real celnet-surface Rust engine.

Seam 4: Client-Side Hash-Based Position Lot Synthesis

Located in gui/src/workspaces/risktransfer/transferModel.ts (lines 6-14)

Synthetic Positions

transferModel.ts splits a portfolio's risk into artificial position lots using an FNV-1a hash function on the client, rather than querying actual server position records from RiskService.ListPositions:

// gui/src/workspaces/risktransfer/transferModel.ts line 6: // • SYNTHESISED position lines. The mock has no per-position store for FI risk... // So a portfolio's selectable "positions" are DERIVED here, deterministically, // by splitting its live RiskBookRisk row into N labelled lots with stable bigint ids.
