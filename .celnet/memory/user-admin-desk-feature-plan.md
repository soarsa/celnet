Original ask + the THREE locked decisions retained below for reference.

Operator's verbatim ask: "lets add a user admin administration and desk grouping so users can be part of a desk group to see the incoming RFQs and allow for reset password and general administration over users. We should have a default admin user like admin@celnet.com with password of password."

**Three approved scope decisions (via AskUserQuestion):**
1. **Auth model = Full server-enforced sessions.** A login issues a session token validated on every RPC — this REPLACES the current client-asserted `EntitlementPrincipal` model (`crates/celnet-server/src/services/access.rs`, which today says transport auth is the deploy layer's job and the wire principal is app-asserted). Heavy option: rewrites the access boundary so every entitlement-gated service validates a real session, not a self-asserted principal. Plan an `AuthService` (Login → session token; Logout; ResetPassword; user CRUD admin-gated) and thread session validation through the gate `access::authorize` fronts.
2. **Desk owns FIX connections.** Add a `desk` owner to each managed connection (`FixConnectionDef` in `config/fix_connections.rs` + proto `FixConnectionSpec`/`Desc` + the GUI wizard/table). Desk members see the monitor + incoming RFQs for their desk's connections (filter `FixAdminService.ListMessages` / the monitor by the caller's desk).
3. Default seeded admin user **admin@celnet.com / password** on first run (like the fix-connections seed). Support reset-password + general user CRUD.

**Implementation notes / constraints:**
- Password hashing: use **argon2** (pure-Rust, OSS Apache/MIT) — satisfies CLAUDE.md rule 7 (no commercial/proprietary). No plaintext storage ever.
- Persist users/desks as JSON stores mirroring `FixConnectionStore` (atomic temp+rename), e.g. `users.json`/`desks.json`, paths from env knobs; gitignore the runtime files like `fix-connections.json` already is.
- Security-sensitive: use the **security-reviewer** agent before committing; validate all inputs; rate-limit login; never log credentials/tokens.
- Mirror the established feature shape: proto service → gRPC impl → WS mirror dispatch+codec → GUI contract/codec/transport/wsTransport/mockSource → hook → workspace/screen. Register a new left-rail "Admin"/"Users" workspace (3 `WorkspaceId` unions: `lib/commands.ts`, `app/AppContext.tsx`, `lib/savedViews.ts` + `WORKSPACES` array; RAIL in commands.ts auto-gets next ⌘N; `WORKSPACE_VIEW` in `app/Shell.tsx`).
- GateGuard hook fires on every edit/write — state importers/affected-API/data-schema/verbatim-instruction before each edit, then retry the SAME op. Run cargo via `/opt/homebrew/opt/rustup/bin/cargo` (no `source $HOME/.cargo/env`).
- Existing login UI `gui/src/app/LoginScreen.tsx` is the RECONNECT fallback, not auth — repurpose/extend carefully, don't assume it's an auth gate.
