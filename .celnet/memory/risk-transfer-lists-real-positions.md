**2026-08-24 — the risk-transfer ticket now moves real positions, for every asset class.
Local main only; NOT deployed.**

The ticket could never transfer anything. It had no way to ask which positions live in a
risk book, so the GUI's `synthesizePositions()` split a book's AGGREGATE risk row into up
to 4 lots and minted FNV-hashed ids. Those ids named nothing the server held, so
`TransferApplier::classify` (`crates/celnet-server/src/services/transfer_apply.rs`) refused
every submit with `position <id> is not booked in either book` — correctly. The screen
looked finished and was inert.

**The root cause was a missing PUBLICATION, not missing math.** The server already held
the routing graph's `risk_book` stamp and read it on the transfer path
(`PositionStore::fx_transfer_view`, `RatesPositionStore::risk_book_of`) — it just never
put it on the wire. Nothing needed to be computed that wasn't already computed.

**The fix generalizes the seam instead of forking it** (the
`uniform-asset-class-architecture` tenet): `RatesPosition` gains `risk_book` +
`net_notional`; `RiskPosition` gains `risk_book`; and **both** carry the SAME
`RiskVectorDesc risk`. That message already existed in the transfer domain and already
maps 1:1 to the GUI's `RiskVector` — so the wire, the SDK and the client all read one
per-position risk shape rather than flat `dv01` on the rates arm and flat greeks on the FX
arm. `StoreSnapshot` carries the risk-book map; `fact_to_position` publishes the canonical
notional-scaled leaf greeks (the numbers the cube aggregates); the rates arm publishes
`rates_linear_exposure` (the measure the pre-trade gate and hedge sizer use).

**Why:** a per-position risk number cannot be derived honestly in a client — the bond arm
needs a cashflow schedule and a memoised analytic derivative — so the alternative to
publishing it is inventing it, which is what the synthesised lots were.

**How to apply:**

- **The half-fix would have shipped a SECOND dead screen.** Wiring only
  `listRatesPositions` leaves the ticket blank for every FX portfolio — and the source
  dropdown offers *all* enabled risk books with no asset-class filter, while the server's
  applier handles FX transfers perfectly well. When you fix an asset-class-specific path,
  check what the OTHER asset classes do on the same screen before calling it done. There
  is now a regression test that selects an FX book and asserts its positions appear.
- **Server-OUTPUT fields must decode as optional.** In the descriptor codec use
  `opt_msg`, not `req_msg` — `set` is still called with `None` for an absent plain field,
  so `req_msg` turns a normal booking request into a decode error.
- **Differential-codec fixtures must carry NON-default values** for new fields
  (`tests/ws_codec_differential.rs`), or the hand/generated byte-equality proves nothing
  about them.
- Adding a `String` to a wire-adjacent SDK struct drops its `Copy`; `to_wire(self)` then
  has to become `to_wire(&self)` because every caller holds it behind a reference.
