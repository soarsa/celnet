For ANY code discovery in Celnet, use **lodestar first**, falling back to Grep/Glob/Read only for non-code text/config. **lodestar 0.8.0 replaced codebase-memory-mcp (CBM)** on 2026-06-22 as the deterministic code-graph + verified-knowledge substrate. **Upgraded to 0.9.0 on 2026-06-29** (machine-global binary `~/.local/bin/lodestar`; 0.8.0 kept as `lodestar-0.8.0.bak`; `lodestar-syncd` 0.9.0 also installed but NOT started — single machine). 0.9.0 = proposal-stream cortex **default-on** + new `knowledge_reward` tool + multi-tenant per-session store routing (OPT-IN isolation — we deliberately leave it OFF so sessions SHARE one store) + bounded-RSS lazy cross-LSP. Note: after a binary swap the **running MCP server stays the old version until Claude Code restarts/reconnects** (`/mcp`); the CLI is new immediately.

Core tools (22): structure — `search_graph`, `trace_path`, `get_code_snippet`, `query_graph`, `get_architecture`, `search_code`, `detect_changes`, `list_projects`, `index_status`, `manage_adr`, `ingest_traces`; verified "why" — `knowledge_get`/`knowledge_put`, `evidence_pack`, `knowledge_todo/check/review/config/export`.

**Project key:** `github.com-soarsa-celnet` (git-remote-derived, pinned in `.lodestar/project-id`; identical on every clone — nothing tied to a developer or machine). Head-less: `lodestar cli <tool> '{"project":"github.com-soarsa-celnet", ...}'`. Binary on PATH after `lodestar install`.

**Health probe before trusting it:** `lodestar doctor --json` ⇒ `ok:true`/`problems:0`, and `price_instrument` must resolve (graph ≈23k nodes on 0.9.0; 22,975 nodes / 74,609 edges as of 2026-06-29). Re-index ⇒ `lodestar index --full <ABSOLUTE-path>` (~5s, deterministic, byte-identical; self-cleans, no `delete_project`). The verified-knowledge projection (≈10.8k events) survives a `--full` re-index.

**Gotchas:** (1) ALWAYS index an **absolute** path — `lodestar index .` records `root_path="."`, corrupts the projects table, and the db auto-deletes. Hooks compute it at runtime (`"$PWD"` / `git rev-parse --show-toplevel`). (2) `lodestar version` (no dashes) is unrecognized and **hangs** (falls through to the stdio MCP server) — use `lodestar --version` / `lodestar doctor`. (3) **Parallel-session worktrees MUST carry `.lodestar/project-id`=`github.com-soarsa-celnet`.** Without it lodestar derives a PATH-keyed project (`Users-adrian-code-celnet-<name>`) with an EMPTY store → that session sees NONE of the shared "why" and shares nothing. The key is NOT auto-remote-derived in a worktree. Fixed 2026-06-29 by pinning project-id (+ copying `.mcp.json`) into all 4 worktrees (`celnet-coord/fz/p1fix/w6x`) — untracked, so lane-branch history untouched; verified all 5 checkouts resolve to the one shared `~/.cache/lodestar/github.com-soarsa-celnet.db`. (4) CLI `search_graph`/etc. from a worktree (and in general) need an explicit `"project":"github.com-soarsa-celnet"` arg. (6) **Reviving a STALE claim in-place is a trap — do NOT patch a live store with re-puts.** `knowledge_put` WITHOUT `id` mints a NEW claim (duplicate, not a revive) — a bulk "re-ground stale" loop creates one dup per claim; `knowledge_put` WITH `id` then *fails* ("failed to store claim") if a contradicted claim collides on the edit-invariant logical key (which the dups now occupy). The reliable reconcile is a CLEAN rebuild: wipe the projection then `replay-knowledge.py` from the committed mirror onto the EMPTY store (replay only duplicates when re-put onto existing claims). Retiring a junk/dup claim works via `knowledge_review verdict=refute reviewer_model=<different-family>` → `retired` (single refute suffices for non-high-stakes kinds; the probe + 225 dups retired this way 2026-06-30). Lesson 2026-06-30: an id-less bulk re-ground polluted the live store with 225 dups; reverted to `contradicted` (active set restored to baseline, committed mirror never touched) — possible lodestar API gap (no clean in-place revive), candidate upstream issue. (5) **`lodestar index --full` WIPES the verified-knowledge projection** (lodestar#18, still open in 0.9.0). Observed 2026-06-29: a `--full` left `knowledge_claim`=0 (all 1636 claims gone from the live store; structural graph fine). It preserves+projects only ALREADY-ACTIVE claims as `(:Claim)` graph nodes and **drops every draft**. **After ANY `--full`, run `python3 tools/lodestar/replay-knowledge.py`** to rebuild the live store from the committed `claims-mirror.json` (1636 claims → ~961 active + ~675 draft; idempotent, ~90s). **Prefer incremental `lodestar index <abs>`** — it PRESERVES `knowledge_claim` (does not wipe). The SessionStart hook auto-replays when `live < mirror`, so normal sessions self-heal; a manual `--full` does not. Note: `knowledge_get` reads the claim table directly (works immediately post-replay); `evidence_pack`/`knowledge_coverage` traverse the projected `(:Claim)` graph nodes and are only reliable via the **0.9.0 MCP server** (a 0.9.0 CLI racing a still-running older MCP server gives inconsistent reads).
